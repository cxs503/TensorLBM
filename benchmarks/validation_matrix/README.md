# TensorLBM validation matrix v1

Nine-case validation lineage with **machine-checkable acceptance**, **one-command
reproduction**, a **two-level convergence requirement** and a **three-level
status table** whose evidence chain lives under the `benchmarks/verified` /
`benchmarks/pending` directory convention.

```
benchmarks/validation_matrix/
├── matrix.json            registry: 9 slots / 10 cases, thresholds, artifacts, repro cmds
├── references.json        anchors: in-repo source file + literal token + sha256 (zero hand-copy)
├── criteria.py            pure rules: error gate, convergence trend, passed/failed/pending
├── reference_audit.py     re-derives every anchor from its cited source (fails on drift)
├── runner.py              list | audit | check | run --case/--tier ci | status --write
├── make_figures.py        field + law-comparison figures with provenance sha256
├── STATUS_MATRIX.md       generated three-level table
├── cases/
│   ├── dam_break_ritter_ci/         new CI-tier case (nx=200/400 + resolution ladder)
│   └── static_droplet_laplace_ci/   new CI-tier case (R=8/12/16 + R=12/16/20)
└── figures/
```

## 1. Why a matrix instead of more cases

The task is explicitly *not* "add more cases": it is to make the existing
evidence **reproducible and machine-judgeable**, so an agent or a CI job can
tell a real improvement from a lucky number. Three properties do the work:

1. **Zero hand-copy anchors.** No reference number is typed into a report. Each
   anchor in `references.json` points at a frozen in-repo source file and a
   literal token in it; `reference_audit.py` re-reads the file, checks the token
   is still there, checks the typed value matches a float parsed from the token
   (or the frozen artifact field it mirrors), and records the source `sha256`.
   An upstream edit or a mistyped digit breaks the audit instead of being
   absorbed silently.
2. **Uniform judgment.** Frozen artifacts and freshly executed runners go
   through the same code: dotted metric paths → `criteria.judge_metric` →
   `criteria.convergence_trend` → three-level status. There is no per-case
   bespoke "looks fine" claim.
3. **Convergence is part of acceptance**, not decoration: every case declares at
   least two levels (two grids, two resolutions, or two independent halves) and
   the level series must stay inside a span band (and be monotone where ≥3
   levels exist). A case whose error is stable *for the wrong reason* (e.g. two
   coarse grids agreeing) is flagged by the span, and a case whose error drifts
   upward with resolution fails even if each level is inside 3%.

### Deviations recorded instead of smoothed over

* `cylinder_re100`: the verified case's own St bookkeeping divides by the
  *lower* bound of the Braza band (0.164 → D64 error −2.4%). Against the band
  midpoint 0.165 the same datum is −3.03%, i.e. marginally outside the 3% gate.
  The matrix reads the artifact's audited convention and records the sensitivity
  in the case notes. Cd error is **not** monotone (−1.53% → −2.55%) although both
  levels are inside the gate; the case is declared `require_monotone=false` with
  the measured span (1.03%) rather than being upgraded to "perfect".
* `ship_resistance_suboff`: the coarse grid (−3.17%) is outside 3%. The case
  pre-registers "finest tier ≤3% AND monotone", so the coarse level is gated as
  *informational* (`tol_pct_by_level: [null, 3.0]`) and the monotone requirement
  still applies over both levels. No threshold was relaxed after the fact: the
  per-level gating mirrors the case's own pre-registration, which is quoted in
  the matrix note.

## 3. The two new CI-tier cases (full chain run in this build)

Both are *framework-first* versions of slots that the assignment lists as
gaps (static droplet / dam break depend on T1; the matrix must exist first).
Each has: a declared analytic anchor, a runner emitting a uniform artifact, a
two-level series, machine judgment, and honest FAIL reporting where the CI
resolution is insufficient.

### 3.1 `static_droplet_laplace_ci` (slot 6)

* Physics: 2-D Shan–Chen single-component droplet, `ψ=1−e^{−ρ}`, library
  `G_lib=+5` (physical `G_eff=−5`), `τ=1`. **Physics is imported** from the
  verified standard-tier case (`benchmarks/verified/laplace_droplet/run.py`),
  not re-implemented — only the CI-scale radius sets and the two-level
  resolution check are new.
* Levels: coarse `R=8/12/16`, fine `R=12/16/20` (domain `L=4R`, periodic).
* Metrics: per-radius surface tension `σ_i = Δp·R_eq` deviation from the fitted
  `σ_eff` (≤3%), fit `R²` (≥0.999), free-intercept fraction (≤3%), and
  `σ_pair_dev_pct` = deviation of each level's `σ_eff` from the two-level mean
  (≤3%, the resolution-convergence statement for this slot).

| level | σ_eff | per-radius max dev | R² | intercept frac | σ pair dev | time |
|---|---|---|---|---|---|---|
| R=8/12/16  | 0.053225 | **4.689%** | 0.996143 | 2.460% | 2.264% | 165 s |
| R=12/16/20 | 0.055690 | 0.822% | 0.999984 | 0.230% | 2.264% | 397 s |

**Honest FAIL of the CI tier + root cause.** With the pre-declared uniform 3%
Laplace gate, the coarse level fails (4.689%, R²=0.9961) and so does the
two-level span (3.87%), while the fine level passes (0.822%, R²=0.99998) and the
fitted σ_eff agrees between levels to 2.26%. The cause is physical, not numeric:
R=8 is only two interface widths (W≈4 in this SCMP model), below the resolvable
radius R≥3W that the Laplace law needs; the same set at R≥12 passes. The status
therefore stays **failed** — no threshold was relaxed and no artifact edited —
and the next build should gate R=12/16/20 vs R=16/20/24 with R=8/12/16 kept as a
documented non-gated ladder. Cost of the CI tier: ~9 min CPU for both sets, which
is the ceiling this case can afford.


### 3.2 `dam_break_ritter_ci` (slot 8)

* Physics: 1-D shallow-water dam break onto a dry bed,
  `tensorlbm.shallow_water` (HLL finite volume + hydrostatic reconstruction),
  `t_end = 5√(h0/g)`, `cfl=0.4`.
* Levels: `nx=200` and `nx=400` (judged), plus a diagnostic resolution ladder
  `nx=800/1600` stored in the artifact so the gate/resolution pairing can be
  audited without re-running.
* Metrics: front law (mass-recovered front from the integral form of the Ritter
  law, 5% gate), depth-profile L2 error inside the wet fan (5% gate), mass
  closure (1% gate).

| nx | front error | profile L2 | mass drift | steps | time |
|---|---|---|---|---|---|
| 200 | +4.512% | 9.825% | 2.2e-14% | 311 | 0.28 s |
| 400 | +2.562% | 6.292% | 2.2e-14% | 623 | 0.60 s |
| 800 (ladder) | +1.433% | 3.837% | 2.0e-13% | 1248 | 1.31 s |
| 1600 (ladder) | +0.793% | 2.315% | 1.1e-13% | 2498 | 3.05 s |

**Honest FAIL + root cause.** The CI tier *fails* the pre-declared 5% profile
gate (9.83% / 6.29%) while the front law passes and converges monotonically
(+4.51% → +2.56%). The ladder shows a clean first-order decrease in both
metrics, crossing the 5% profile gate near `nx≈700`: the CI tier is
under-resolved for the profile metric, it is not evidence against the scheme.
The pre-existing standard-tier runner (`benchmarks/dam_break_ritter`, nx up to
1600) also reports `front_err_mass` up to 6.4%, i.e. it would fail the same 5%
front gate — so the gate/tier pairing needs re-calibration, and that is recorded
here instead of quietly loosening the gate to make the number green.

## 4. Automation

```bash
# 1. provenance gate: every anchor still derivable from its cited source
python benchmarks/validation_matrix/reference_audit.py

# 2. judge all frozen evidence (no simulation)
python benchmarks/validation_matrix/runner.py check

# 3. run a case end-to-end and write its status file
python benchmarks/validation_matrix/runner.py run --case dam_break_ritter_ci

# 4. run every CI-scale case
python benchmarks/validation_matrix/runner.py run --tier ci

# 5. regenerate the three-level table + per-case status files
python benchmarks/validation_matrix/runner.py status --write

# 6. figures (field comparison + convergence ladder + Laplace law)
python benchmarks/validation_matrix/make_figures.py
```

Tests: `python -m pytest tests/test_validation_matrix.py -q` covers the
criteria rules (including the "declared negative result is never upgraded"
rule), the matrix schema (all nine slots present, ≥2 levels, path/length
consistency, every repro command resolves), the reference audit, status-file
consistency, and one complete CI case end to end (dam break at nx=100/200,
~6 s). Set `TLBM_SKIP_MATRIX_CI=1` to skip the end-to-end case.

## 5. Adding a case (protocol)

1. Put the anchor in `references.json`: `source` (repo file), `token` (literal
   string in it), `value` **or** `formula`; run `reference_audit.py` — if the
   anchor cannot be re-derived from an in-repo source, the case stays `pending`
   (WITHHELD) instead of quoting a number.
2. Add a runner under `cases/<id>/run.py` that writes a uniform `result.json`
   with `levels[i].metrics.<name>`; keep the CI tier under a few minutes.
3. Register the case in `matrix.json`: slot, levels, one metric spec per
   quantity (`kind`, `tol_pct` or `tol_pct_by_level`, frozen-artifact dotted
   `paths`), convergence rules, and the `repro.cmd`.
4. Run `runner.py run --case <id>` then `status --write`; commit the artifact,
   the status file and the table together. Never edit a status by hand.

## 6. Scope and limitations

* The matrix does **not** re-run the expensive frozen tiers (SUB-Off 3.4 h,
  cavity 159 s/grid, sphere multi-hour): it re-judges their recorded numbers and
  pins them by sha256. Re-running is a separate, budgeted activity driven by
  `repro.cmd`.
* `channel_turb_re180` and `rayleigh_taylor_rt` are kept as `failed` on purpose:
  a negative result with a root cause is a matrix asset, and it prevents the
  same two model classes from being re-funded under a new case name.
* `ship_wave_michell` is `pending` (WITHHELD) because the primary criterion was
  never measured; the blocker is the 3-D cost, not a numerical disagreement.
* The CI tiers trade resolution for runtime: for the dam break this is *visible*
  (profile gate fails) and quantified by the ladder; for the droplet the usable
  radius range is bounded by the interface width (~4 cells in the SCMP model),
  so R<8 is not physical and R=20 is the CI cost ceiling.
## 5. Repair round m15915 — the matrix now records its own runs

Matrix v1 could judge frozen artifacts but could not prove *when, where and from
which commit* those artifacts were produced, and two bookkeeping defects made a
fresh `pytest tests/test_validation_matrix.py` disagree with the committed
status files.  Both are fixed here; nothing about a verdict was relaxed.

**Bookkeeping fixes (what actually broke).**

1. `cylinder_re100_dfg` was registered with metric paths
   `grids.<D>.err_pct.<metric>`, but the case's own `aggregate()` writes
   `per_metric.<metric>.err_pct.<D>`.  The registry therefore resolved nothing
   and the case sat at *pending: metric paths unresolved* even though a D20
   artifact existed.  The paths now match the artifact schema (matrix v1.1) and
   the missing levels are reported as missing levels, not as a schema failure.
2. `benchmarks/pending/static_droplet_laplace_ci/validation_status.json` had
   never been written, so `test_status_files_match_fresh_evaluation` failed.
   `runner.py status --write` regenerates every status file from a fresh verdict;
   the test now guards against the regression.

**Run ledger (`runledger.py`).**  Every execution started through
`runner.py run` writes, under `artifacts/validation_matrix/runs/`:

```
<UTC>__<case>/manifest.json   git sha + dirty flag, matrix/references sha256,
                              host, cpu count, torch version, thread env,
                              repro_cmd, rc, elapsed, artifact sha256, verdict
<UTC>__<case>/run.log         full stdout+stderr of the repro command
<UTC>__<case>/status.json     the verdict of that run
index.jsonl                   append-only index (one line per run)
```

`runledger.py verify` re-hashes every manifest against the index, so a ledger
entry cannot be edited to look better after the fact.  A non-zero exit code is
recorded as execution evidence rather than dropped.

**Reference-vs-got table (`make_benchmark_table.py`).**  Emits
`BENCHMARK_REF_VS_GOT.{json,md}`: per case, per metric, per level — reference
value + anchor source sha256, measured value, signed error, tolerance, pass
flag, convergence span, repro command.  `--check` fails if any `passed` case
contradicts its own numbers.

**Entry point + integration callers.**  `python -m benchmarks.validation_matrix
<cmd>` is now a first-class entry, `make validation-matrix` runs the whole
contract locally, `.github/workflows/validation-matrix.yml` runs it on every
change to the matrix/cases/anchors (honest FAILs do not fail the job — a
bookkeeping contradiction does), and each case runner is asserted to import the
real `tensorlbm` kernels (`test_cases_delegate_to_library_kernels_...`).

**Exit-code semantics.**  `runner.py run` returns non-zero only for execution
failures.  `--strict` re-enables failing on a `failed` verdict (release gating).
An honest FAIL is a recorded result, never a silently green build.
