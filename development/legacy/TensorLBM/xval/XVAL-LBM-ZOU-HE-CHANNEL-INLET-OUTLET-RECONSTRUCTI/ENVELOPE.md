# ENVELOPE.md -- validity envelope of the Zou-He channel closure

Extension of `REPORT.md` (module / setup / primary arm) and `REFINEMENT.md`
(h-study).  Those two documents validate the closure at **one** point of
parameter space, `drho = 4e-3`, `tau = 0.65`.  This document answers the two
questions a reader of the 0.35 % headline actually has:

* how far does it survive in the **imposed density difference** (`drho`,
  which sets the Mach number and the acoustic transient), and
* how far does it survive in the **relaxation time** (`tau`, which sets the
  half-way bounce-back wall position -- the classic `tau`-dependent error of
  this discretisation).

Everything below is generated by `make_envelope_report.py` from JSON records
in `artifacts/xval_zouhe/envelope/` (library solver) and
`artifacts/xval_zouhe/indep_*.json` (independent code path).

## 1. Independent re-implementation (`independent.py`)

`REPORT.md`'s 0.35 % comes from one code path, so it could in principle be an
artefact of that path.  `independent.py` re-solves the same case with a
**separate implementation**: pure NumPy, textbook D2Q9 index table (the
library uses the OSS permutation `2=(-1,0), 3=(0,1), 7=(1,-1), 8=(-1,-1)`),
the Zou-He closure re-derived from mass + x-momentum + y-momentum, and an
explicit loop over the nine directions for streaming.  It imports nothing
from `tensorlbm`.

## 3. Relaxation-time axis, `drho = 4e-3`, H = 16, nx = 128

`delta` is the effective wall offset: the mean distance between the roots of a
least-squares parabola fitted to the discrete mean profile and the exact wall
positions `y = 0.5`, `y = H + 0.5`.  It is a lumped diagnostic, not an
assumption -- its usefulness is that one number predicts the whole error.

| 0.55 | 0.0167 | 2.008e-02 | 4.562e-03 | 1.692e-03 | +0.0152 / -0.0152 | 3.806e-03 | 6.926e-06 |
| 0.60 | 0.0333 | 1.004e-02 | 3.904e-03 | 1.643e-03 | +0.0147 / -0.0147 | 3.687e-03 | 2.455e-06 |
| 0.65 | 0.0500 | 6.693e-03 | 3.535e-03 | 1.531e-03 | +0.0137 / -0.0137 | 3.434e-03 | 8.197e-07 |
| 0.80 | 0.1000 | 3.347e-03 | 2.053e-03 | 9.045e-04 | +0.0081 / -0.0081 | 2.031e-03 | 3.117e-07 |
| 1.00 | 0.1667 | 2.008e-03 | 1.314e-03 | 5.789e-04 | -0.0052 / +0.0052 | 1.302e-03 | 2.574e-07 |
| 1.50 | 0.3333 | 1.004e-03 | 1.703e-02 | 7.404e-03 | -0.0674 / +0.0674 | 1.686e-02 | 2.427e-07 |

Best cell: `tau = 1.00` at 0.131 %; worst: `tau = 1.50` at **1.703 %**, i.e. 13.0x the floor.
`tau` is therefore the real axis of this closure: it is 13.0x more
damaging than a 40x change of `drho`.  The reported `tau = 0.65` point is
representative of a *typical* BGK setting, not of the worst case.

### Empirical wall-position law
Fitting `delta(tau) = a + b (tau - 1/2)^2` over the six `tau` cells gives
**a = +0.01555  (= 1/64 = +0.01562),  b = -0.08297  (= -1/12 = -0.08333)**,
with a maximum residual of 1.14e-04 lattice units over
`tau in [0.55, 1.50]`.  The `(tau - 1/2)^2` dependence is the classic
half-way bounce-back wall-position error, here measured rather than derived;
the constant term is the discretisation bias of the parabola fit and is *not*
claimed as a physical result.

The error model that comes out of it is one line:
```
rel_umax ~= 4 |delta(tau)| / H
```
which reproduces the measured `rel_umax` to within 5 % over all six `tau`
cells (worst cell the smallest `tau`, where the absolute error is largest; see
the table and `figures/fig8`).  It is a one-parameter explanatory model, not
an identity.  The factor
4/H is what one expects from a profile whose amplitude scales as `H_eff^2`
with `H_eff = H - 2|delta|` -- so the entire error budget at these
resolutions is *wall position*, and the Zou-He closure contributes nothing
measurable on top of it.  This is the quantitative version of the negative
result already noted in REPORT.md section 5.

## 5. Pitfalls found while building this extension

* **Streaming window in the wrong coordinate frame.** The independent
  implementation first clipped the pull window with
  `max(dest_lo, src_lo)` -- mixing destination and source coordinates.  The
  effect was silent: the two end columns were never streamed, the closure then
  read stale populations and produced a 19 % amplitude error with a
*perfect* profile shape (shape L2 = 1.5e-3, identical to the healthy run).
  A shape-only metric would have passed.
* **Initial density ramp off by `nx-1`.** `np.linspace(-drho/(nx-1), 0, nx)`
  drops by `drho/(nx-1)` instead of `drho`, leaving a nearly uniform density.
  The interior profile still converged to within 0.3 %, so `rel_umax` looked
  healthy while the end-to-end mass defect was 2.7e-2 -- by far the most
  sensitive diagnostic for this class of bug.  It is now reported for every
  cell of the envelope.
* Both bugs were caught by cross-comparing against a second implementation
  step by step (one step from an identical state, then 20/500/2000/4000/8000
  steps), which is why `tests/test_zou_he_channel_envelope.py` now performs
  that comparison on a small case.

**Declared limit of the verified region:** `H = 16`, `L/H = 8`, `tau` in

static no-slip walls, BGK collision.  Outside it (curved/moving walls, MRT,
turbulence, `tau` far above 1.5) nothing here is claimed -- `tau = 1.5`
already shows the closure degrading by an order of magnitude, which is a
warning for anyone reusing it at high viscosity.
