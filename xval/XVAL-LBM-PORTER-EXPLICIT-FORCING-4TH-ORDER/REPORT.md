# XVAL-LBM-PORTER-EXPLICIT-FORCING-4TH-ORDER — 第 1 轮 · 开源对标（PorousMediaSimulation/openLBMPM）

**锚点**：`XVAL-LBM-PORTER-EXPLICIT-FORCING-4TH-ORDER`
**对标对象**：`PorousMediaSimulation/openLBMPM` 的 `porter-explicit-forcing-4th-order` 做法（Porter et al., PRE **86**, 036701 (2012) 显式力四件套 + 4/8/10 阶各向同性力 stencil）
**判据（owner）**：对标误差 **≤ 15%**；拉伸 **≤ 3%**
**结论一句话**：**单组元强制流道 PASS（NY=34 误差 3.2e-4，拉伸达标）**；**两组元分层高粘度比**：四件套把误差从 legacy 的 60.6% 降到 40.9%（NY=34，判据要求的 3 倍区分度达成 3.1×，NY=66 时 18.1% vs 56.3%），但**在 M≥5 的所有测试网格上仍 > 15% → 该子项 honest-FAIL**，机制已定量定位（见 §五/§六）；**参考记录的第二种读法（doc_seq）被证伪**（净动量注入 F 而非 ½F，与同一记录里"速度回收含 ½F"自相矛盾，实测误差恰 50.0%）；**"4 阶 stencil 压伪电流"这一参考主张首次被量化**：iso4 与 DQ9 核严格同一族（A6=0.6，伪电流指标 3.12e-3 完全相同），六阶 stencil 把液滴切向伪力降到 9.1e-4（**3.4×**，方向与参考主张一致）。

## 一、问题与参考（ref 出处）

MCMP（两分量）伪势 LBM 的**显式力**格式：力如何进入分布函数、宏观速度、平衡态速度，直接决定粘度比上限与分层稳定性。参考实现的四件套（平台源码读码记录 `docs/oss-inventory-openLBMPM.md` §II.2 / §4.3，逐条带 file:line）：

| 要素 | 参考记录位置 | 做法 |
|---|---|---|
| 力 PDF | `ExplicitD2Q9GPU.py:255`, `:271-276` | `F_i=(F·(c_i-u_eq)) f_i^eq/(ρ c_s²)` |
| 碰撞前 | `:278-287` | `f ← f − ½F` |
| 碰撞 | `:294-304` | `f ← f + (f_eq − f − ½F)/τ + F` |
| 总速度 | `:311-332` | `u = [ΣΣ f c + ½(F₀+F₁)]/ρ_tot` |
| 粘性加权平衡速度 | `:340-363` | `u_eq = Σ[(Σ f c + ½F)/τ]/Σ(ρ/τ)` |
| 各向同性力 stencil | `ShanChenD2Q9.py:1675-1695`, `ExplicitD2Q9GPU.py:392-624` | isotropy 4/8/10，`Σ w c_x² = 1` |

**零手抄声明**：本机外网被策略拦截（`curl github.com` → REJECTED），参考仓亦无许可证 → 一律**只按公开论文＋平台读码记录**实现，未复制任何源码行；参考实现的权重字面量不可得（生态摩擦 F1），故 stencil 由定义不变量（`Σw c_x²=1` + 各阶各向同性矩消失）**自行反解**，并在此报告实测各向同性常数（§三）。

## 二、方法与实现

新增仓内能力 `src/tensorlbm/porter_forcing.py`（四件套 + 各向同性 stencil + 半步反弹流送），对标工装 `xval/XVAL-LBM-PORTER-EXPLICIT-FORCING-4TH-ORDER/`：

| 文件 | 角色 |
|---|---|
| `ref/porter_ref.py` | **REF 臂**：独立逐行转写（自带格子常数与逐方向循环，不 import 仓库模块） |
| `got_driver.py` | **GOT 臂**（走仓内 API）+ **legacy 控制臂**（原式 Shan-Chen：力并入 `u_eq_i=u+τ_iF_i/ρ_i`，无半点力）+ 解析解 |
| `run_xval.py` | B1/B2/B2t/B3 四项算例、`artifacts/result.json` |
| `make_figures.py` | 三图 + `artifacts/table.md`（程序化生成，零手抄） |
| `predeclared.json` | 决策/替代方案/门槛/停止规则/混杂因素（**先于任何数字**落盘） |

**两个算例的解析锚**（自解，不抄公式）：单相/两层 Stokes 直通道解由 2×2 线性方程组直接求解（`got_driver.layered_stokes`）：`u''=−g/ν`，两壁无滑移、界面速度与切应力连续。

**为什么 B2 用"解析解为初值"（fixed_point）**：轻质层动量扩散时间 `H²/ν_light ≈ 32²×60 ≈ 61 000` 步，远超从静止起步的预算；fixed_point 直接度量"离散格式是否保持解析解"（书账错必在 <1000 步内暴露，doc_seq 即如此），从静止起步的 B2t 单独保留为敏感性项。

## 五、收敛性 / 参数敏感性（≥2 点）

1. **网格收敛（M=1）**：3.43e-4 (H=32) → 1.28e-4 (H=64) 一阶–二阶之间（界面 tanh 宽度固定 1.5 格 → 一阶主导）。
2. **网格收敛（M=10）**：5.04e-1 (H=16) → 4.09e-1 (H=32) → 1.81e-1 (H=64)，**一阶**（界面宽度/通道高比固定）；legacy 同网格 6.56e-1→6.06e-1→5.63e-1（几乎不收敛）→ 二者比值 3.1×，判据的"区分度"门槛达成。
3. **粘度比敏感性**：doc_literal 0.219 (M=5) → 0.409 (M=10) → 0.802 (M=100)；legacy 0.409 → 0.606 → 3.40e+3（M=100 直接崩）。
4. **实测有效粘度（机制定位）**：由 LBM 剖面曲率反演，轻质层 `ν_eff/ν_nominal` = **4.45 (H=16) → 3.04 (H=32) → 1.23 (H=64)**（M=10）；即**扩散界面把粘度反差抹平**，实测粘度比 M_eff≈2.2（M=10, H=32）远低于标称 10 → 这正是 40.9% 误差的来源，且随界面分辨上升单调收敛（H=64 已到 1.23×）。
5. **from_rest vs fixed_point**：M=1、H=32 两者同为 3.25e-4（瞬态不污染判据）；H=64 的 from_rest 固定预算（13 200 步）不够，误差 5.07e-3，全部臂同向偏移 → 记录为**预算伪影**而非格式缺陷。
6. **碰撞代数两种读法**：doc_literal 3.25e-4 vs doc_seq 5.00e-1（净注入恰为 2 倍的关系）→ 记录歧义消解为"碰撞项的 −½F 就是碰撞前那次减法"。

## 六、失败模式 + 工件

- **honest-FAIL 子项**：两组元分层 M≥5 在 H≤64 全部 > 15%（最好 18.1%）。失败机制=**扩散界面粘度抹平**（§五第 4 点），非书账错误（M=1 与单组元均 <0.1%）。接棒方向：参考实现的分层算例依赖**伪势相互作用力维持的分离界面**（本单 G=0 无相互作用，界面仅由初值给定且会数值扩散）；下一轮应在 Porter 四件套之上叠加 `G<0` 的 SC 力与共存密度初始化，并把界面宽度作为被控变量扫描。
- 初版书账缺陷（已修）：早期用 `(cu²−u²)/(2c_s⁴)` 的 D2Q9 平衡态 → 质量按 `3u²/步` 泄漏（4000 步丢 33%），改为 `(cu²−c_s²u²)/(2c_s⁴)` 后质量守恒 1e-13；已入单测锁定。
- 力 PDF 除以 ρ 的数值陷阱：缺席分量残差 ρ~1e-3 时 `f^eq/ρ` 除零放大（3 步炸）→ 改为代数比 `f^eq/ρ=w_i(1+cu/c_s²+(cu²−c_s²u²)/(2c_s⁴))`。
- 生态摩擦 **F1**：外网被封，无法取参考源码逐行复核（依赖平台读码记录 + 论文）；**F2**：参考仓无许可证 → 只能算法级吸收；**F3**：`oss_solutions` 表对 agent 只读受限（`psql` permission denied），开工三查只能用平台文档副本。
- 工件：`artifacts/result.json`（全部 run 原始数）、`artifacts/table.md`（程序化生成）、`figures/fig1_layered_profiles.png`、`fig2_convergence.png`、`fig3_stencils.png`、单测 `tests/test_porter_forcing.py`（13 项全绿）。

## 七、TensorLBM vs OSS 差异清单（做法 / 参数 / 边界条件）

| 维度 | openLBMPM（记录） | 本仓（本单） | 影响 |
