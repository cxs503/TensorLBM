# XVAL-LBM-IBM-EPSILON-GRAM-IMPLICIT-CORRECTION — TensorLBM vs joconnor22/LIFE

Mission m17862 · 2026-11-13 · branch agent/m17862 · 判据: 对标误差 <15% (owner 精度标准)

## ① 案例介绍（物理背景 / 几何 / 参数表）

**对标对象**: joconnor22/LIFE (commit 2af2428) 的 `ibm-epsilon-gram-implicit-correction`
——IBM 力传递的隐式修正：对每个 Lagrangian marker 求解 Gram 线性系统 `A·ε = 1`，
把修正乘子 ε 乘进力扩散 `F_lattice += force·ε·ds·δ`，补偿离散 Dirac 不归一与
邻近 marker 支撑重叠。关键做法全部从 OSS 源码查得（零手抄，逐行引用见 predeclared.json）：

| 规则 | OSS 出处 |
|---|---|
| 3 点正则化 δ（支撑 \|r\|≤1.5） | inc/Utils.h:220-231 |
| 支撑构建（5×5 窗、无周期回绕） | src/IBMNode.cpp:140-180 |
| ds = 同体最近邻距 | src/IBMNode.cpp:186-205 |
| 扩散 `F += force·ε·ds·diracVal` | src/IBMNode.cpp:73-74 |
| Gram 系统 `A[i,j]=Σ_s w_i(s)·δ(\|x_j−x_i(s)\|)·δ(\|y_j−y_i(s)\|)·ds_j`，解 `Aε=1` | src/Objects.cpp:235-320 |
| 重算节奏：刚性体 t=0 一次，柔性体每步 | src/Objects.cpp:271-272 |

**本仓现状（A3 基线）**: `src/tensorlbm/ibm.py` 的 `ibm_force_spread` 用 hat/4pt 核、
无 ε 修正；`ibm_force_transfer.direct_forcing` 为速度型直接强迫（非力扩散路径）。

**主实验（力传递往返）**: 64×64 周期网格，圆心 (32,32)、半径 R=10 的 marker 环，
N∈(16, 32)，ds=2πR/N；目标力场：常值 (1,0) 与径向 (cosθ,sinθ)。
**次实验（物理）**: 128×64 周期盒，D=8 固定圆柱，u=0.1，ν=0.008 → Re=100，
力型 IBM（LIFE 3pt 核 + 2 次 Guo 校正步），200 步时均阻力系数。

## ② 怎么做的（方法 / 流程 / 关键设置 / 工具链）

1. **移植** `src/tensorlbm/ibm_epsilon_gram.py`：LIFE 3pt δ、支撑构建、computeDs、
   Gram 求解（torch.linalg.solve）、扩散/插值（循环版 + 稀疏矩阵向量化版）。
2. **一致性自检**：向量化版 vs 循环版 max diff = 4.4e-16（spread）/
   2.2e-16（interp）→ 语义一致（pass=True）。
3. **臂设计**（predeclared.json 预声明，未事后调参）：
   - A1 = LIFE 3pt δ + ε-Gram 修正（移植）
   - A2 = 同一 LIFE 3pt δ、ε=1（唯一变量=修正）
   - A3 = 本仓现有 ibm_force_spread（差异清单用）
4. **KPI**：往返 L2/max 相对误差（ref=目标力，精确）、总力守恒偏差、ε 统计、Cd。
5. 工具链：torch float64 单进程 CPU；`run_xval.py` 一键复现；结果 `results.json`。

## ⑤ 注意点（坑 / 局限 / 适用范围）

1. **移植 bug（已修）**：初版 `life_delta_3pt` 在内支对 `ra` 做了 `clamp(max=1/3)`，
   在 r=0.5 处把 0.5 错算成 0.6055（1D 归一和 1.211≠1）；改为对根号内 clamp(min=0) 后
   与 OSS 参考逐点一致（11 点全 match）。
2. **稳定性**：力型 IBM 无校正步时 8 步内发散（3pt 核支撑窄、力集中）；加 2 次
   Guo 校正步后 A1/A2 均稳定（与 in-repo direct_forcing 一致）。
3. **总力偏差是修正的固有代价**：ε 使往返成为恒等，但沉积总力被放大 ~ε 倍
   （N=16: +2.5%；N=32: +85%）。LIFE 中该偏差由 FEM 结构侧闭环吸收；
   纯 LBM 力型 IBM 若采用本修正，需评估该偏差是否可接受（本单如实记录，不粉饰）。
4. **N=32 径向场 A1 往返 2.2e-3**：marker 重叠使 Gram 系统耦合，修正不再精确到机器精度，
   但仍比 A2（4.6e-1）好 ~200×。
5. **局限**：仅 2D 路径；LIFE 的 UNI_EPSILON（全局单 ε）选项未移植；
   未运行 OSS 二进制（C++/LAPACK/Boost 依赖 + 完整 FSI 工况），为语义级移植。
6. 物理臂 blockage D/ny=12.5% 会抬高 Cd，文献带已按此放宽。

且比未修正好 ~200×）。物理臂 Cd 两臂均在文献带内。

## 本仓 vs OSS 差异清单（做法 / 参数 / 边界条件）+ 移植取舍

| 维度 | OSS (LIFE) | 本仓移植 | 取舍 |
|---|---|---|---|

| 校正步 | 无（FEM 侧闭环） | 2 次 Guo 校正步（稳定所需） | 偏差：纯 LBM 力型 IBM 需要，LIFE 靠 FEM 闭环 |
