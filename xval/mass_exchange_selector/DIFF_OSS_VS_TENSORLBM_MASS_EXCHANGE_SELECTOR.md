## 5. Transplant trade-offs (the deliverable recommendation)

1. **Tolerance transplant (kappa 1e-2 → 3e-3) is free.** It is already a public
   argument (`cell_conversion_threshold`); arm `C_hybrid` is exactly that arm.
2. **The unconditional `NO_IFACE_NEIGH | NO_FLUID_NEIGH` demotion needs a code
   change and is the dominant source of decision divergence.** It fires on
   interface cells that still carry substantial mass, so it is a *modelling*
   choice (how aggressively the interface layer is kept one cell thick), not a
   numerical tolerance. Not transplanted by this XVAL.
3. **The `eta`-weighted split should not be copied verbatim.** In the upstream
   collection loop (`update_types.py:106-110`) the donor at `d` deposits into
   `d - v[n]` while weighting by `v[n]·n`, so the deposit lands *anti-parallel*
   to the eta direction (i.e. toward the liquid side). Any transplant has to
   decide explicitly whether that is intended; the repo's isotropic `1/n_recv`
   split plus its step-level inventory clamp already conserves mass to
   <0.05 % drift, so the directional refinement buys nothing measured here.
4. **Receiver-set difference is structural, not tunable.** Making demoted
   neighbours receivers (OSS) instead of promoting credited gas cells (repo)
   changes *where* mass goes when a whole interface layer converts at once;
   the repo's clamp compensates at step level, which is why the inventory-drift
   metric does not separate the arms (see the falsified H2 in the report).
