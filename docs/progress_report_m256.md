## 2. 怎么做的（方法/流程/关键设置/工具链）

### 2.1 质检流程
1. **登录平台**: 通过 `$TENSOR_AGENT_USER/$TENSOR_AGENT_PASS` 获取 JWT token
2. **拉取报告**: GET `/tensor/reports/{id}` 获取 markdown 全文及 figures 元数据
3. **结构审查**: 逐篇检查五节（目的/方法/关键结果/审计/局限）完整性
4. **数字溯源**: 每篇抽 3 个关键数字，到对应 mission 的 docs/*.md 与 artifacts/*.json 中 grep 复核
5. **honest-FAIL 检查**: 原单结论若为 FAIL，报告不得粉饰为 PASS
6. **图件检查**: 场量云图+比较曲线两类齐备；缺任一类须有明确理由
7. **误差判定检查**: 关键量 vs 基准误差逐项列出且显式回答是否<3%
8. **结论审查**: 检查是否有超出数据支撑的断言

### 2.2 工具链
- Python urllib: API 调用
- Python json: 工件数据解析
- grep: 文档内数字定位
- 平台 API: report 发布

## 5. 注意点（踩过的坑/局限/适用范围）

### 5.1 图件 png_base64 缺失问题
- 报告 160/161 的 figures 数组均有条目但无 png_base64 字段
- 报告 markdown 中使用占位符引用而非实际嵌入图像
- 这可能是报告发布流程的技术缺陷，非内容质量问题
- 建议：平台应强制要求 figures 包含 png_base64 或明确标记为 placeholder

### 5.2 场量云图豁免理由缺失
- Report 160 (SUBOFF 3D 绕流): 应有压力/速度云图，但报告未提供且未声明理由
- Report 161 (Stokes 1D 剖面): 云图不适用，但报告未明确声明
- 建议：owner 应在质检模板中增加"图件豁免理由"必填项

### 5.3 局限性
- 数字溯源仅抽查 3 个关键数字，未覆盖全部数据
- 图件内容真实性无法验证（无 png_base64 时无法比对图像内容）
- 未检查报告 markdown 中的公式渲染正确性
