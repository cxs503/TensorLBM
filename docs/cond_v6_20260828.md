## TL;DR

v5 用一条线性通道 `log10(sail_x_mult)` 恢复了 sail 轴符号（ratio
0.000→0.531），但趋势**幅度**仍欠校准（serving 基线 COMB-10 ext ratio
1.028）。本 PR 把实验侧验证过的 13 列条件向量落成 src：v5 的 9 列 +
`[log10(sail_x_mult)², log10(l_over_d_mult), log10(nose_len_mult),
log10(stern_len_mult)]`（"v6qx" 布局）。10 种子 × 382 行语料：
**ext 中位 ratio 0.992**（全战役系列最佳；每 Re ratio
[0.984, 0.992, 1.007]，全 sweep 斜率距真值 −1.6/+0.7%），canon 0.905，
B-grid 0.889，test55 0.511%，sign −1，0 个负成员——**在每个趋势口径上
都支配现行 serving 基线**（COMB-10：ext 1.028 / canon 0.704 / B 0.867）。
预注册 WIN 门未全过（B-grid 0.889 差 0.011、slender 不敌 v5x382 控制
臂），故默认 `cond` 仍为 v5；v6 以纯新增路径落库，等 stabilization 决策。
20 种子池 ext 0.942（漂移 −0.050），方向稳健。

## 1. 通道设计（新增函数，默认路径零改动）

- `tensorlbm/ai/drag_cond.py`
  - `SAIL_AXIAL_QUAD_CHANNEL_NAME = "log10_sail_x_mult_sq"`；
  - `sail_axial_quad_channel(sail_x_mult)`：**v5 同一 log10 值的平方**
    （`np.square(sail_axial_channel(...))`，无符号列，永远与线性列成对
    出现）；mother=精确 0.0；
  - `HULLFORM_AXIS_CHANNEL_NAMES` + `hullform_axis_channel(mult)`：三条
    船形长度比轴的共用 log10 通道原语（校验有限正，标量或 1-D）；
  - `condition_v6(re, u_in, sail_scale, fin_scale, geometry, sail_x_mult,
    l_over_d_mult=1.0, nose_len_mult=1.0, stern_len_mult=1.0)`：(N, 13)；
    **前 9 列 = `condition_v5` 逐位相同**；mother 设计下 4 条新列全为精确
    0.0（v6 在 mother 上数值退化为 v5）。
- `tensorlbm/ai/active_learning.py`
  - `hullform_condition_rows_v6(params, re_list, ...)`：(N, 13) 服务侧行
    构造（v5 行 + 4 列，`params` 缺省轴 = 1.0）；
  - `corpus_cond_v6(index)`：语料 (N, 13) 矩阵；缺轴列的语料 = 该轴全
    mother → 通道全 0；
  - `corpus_with_cond(..., cond="v6")`（挂 `cond_v6` 列）、
    `retrain_ensemble(..., cond="v6")`（进 member meta）、
    `predict_design(..., cond_version="v6")`——默认 v3 不变，v5 路径
    一字未动；
  - **"v6" → "v6qx" 映射**：实验侧 `cond_matrix(corpus, "qx")` 的列序是
    `corpus_cond_v5 ⊕ [log10(sx)², log10(lod), log10(nose), log10(stern)]`，
    `cond="v6"` 在 src 里就是这一列序（`COND_V6_CHANNEL_NAMES`），实验
    的 q/x 变体（10/12 列）不进 src。
- `tensorlbm/ai/inference_service.py`：**零改动**——backend 的 cond 宽度
  校验早已从成员架构读取（`cond_embed[0].in_features`，#258 已改），无
  cond 版本白名单需要加。

**逐位不变性由测试钉死**：`tests/test_drag_cond.py::TestConditionV6`
（9 列前缀 `.tobytes()` 逐位、mother 4 列精确 0、代表变式值
sail_x 1.3 → col9=log10(1.3)²、l_over_d 1.2 → col10=log10(1.2)、
col9=col8²、标量广播 + 校验、确定性）与
`tests/test_active_learning.py::TestConditionV6Path`（v5 行逐位前缀、
语料矩阵宽 13 + 全 mother 全 0、`corpus_with_cond(cond="v6")` 后
`split_random` 与 v5 **逐成员相同**〔base 行资格中性〕、
`retrain_ensemble(cond="v6")` → `backend.cond_dim == 13` →
`predict_design(cond_version="v6")` 端到端且预测随轴变化、13 列宽度
守卫、非法 cond_version raise、CPU 确定性重训）。

## 3. 双口径门核算（诚实）

**预注册 WIN 门未全过——差 2 个子门**：

1. **B-grid 0.889**，差 0.011 未过 >0.9 的子门（COMB 0.867、v5x382
   1.220、v6x 0.922 过、v6q 0.929 过——但两臂各有其它硬伤）。
2. **slender 未击败 v5x382 控制臂**：18.681 % vs 16.843 %。显式轴通道
   **不修复**恒定欠预测偏移（×0.812 vs ×0.830；COMB 无 slender 支持
   33.681 %，×0.662）。通道做到的是把偏移**变平**（行 ratio std 0.0060
   vs 0.0266）并坍缩成员方差（成员 MAPE 16.9–20.9 % vs 6.8–31.8 %）——
   与两阶段 SDF 同质的定性签名，但常数反而略离 1。两阶段 SDF
   （10.71±0.11 %，不同语料 350+56 与编码器）仍是 slender 的解。

**对 serving 基线的比较（第二口径）——全口径支配**：v6qx 对 COMB-10
ext 0.992 vs 1.028、canon 0.905 vs 0.704、B-grid 0.889 vs 0.867、
slender 18.681 % vs 33.681 %、test55 0.511 vs 0.519、fresh o12/A/B
0.136/0.044/0.085 vs 0.143/0.086/0.159（fresh M 0.515 vs 0.401 单项
让步）、0 负成员（COMB 0.44–1.65）。

**种子池漂移**：20 种子池（`eval_v6qx_e20.json`）ext 中位 0.942
（每 Re [0.968, 0.942, 0.930]），10→20 种子漂移 −0.050——方向稳健，
幅度未稳，per-member 离散 0.25–2.04（仍 0 负）。canon 成员 ratio 在
所有臂里都野（v6qx 20 种子 [−0.17, 2.30]）——窄对口径依旧是种子
敏感面。

**corpus 混合的代价（Q1）**：把 slender56 倒进 v5 语料而不加通道
（v5x382）不改善 ext（1.034 ≈ COMB 1.028）但**毁窄口径**（canon
0.704→0.243，B-grid 0.867→1.220，2 个负成员）——slender 行要进
serving 语料就应带 v6qx 宽度（v6qx 的 canon/B/test55 全部恢复）。

  ×0.81 恒定偏移不因通道消失。

  （W=12/13 时角落行 271 从 reject 变 review），跨宽度比较判计数
  不可比（实验 D6）。
