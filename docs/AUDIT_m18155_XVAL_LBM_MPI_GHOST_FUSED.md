## 3. New finding — the analytic reference itself is mis-set (7.25 pp of the reported failure)

`case.py::TGV.decay` returns `exp(-2*nu*k^2*t)`, and `predeclared.json::baseline_control` wrote that formula
down **before** any arm ran. But the delivered initial condition is the 3-D ABC field
`ux = U0 sin(kx) cos(ky) cos(kz)`, `uy = -U0 cos(kx) sin(ky) cos(kz)`, `uz = 0`: although `uz = 0`, every
velocity component carries the wave vector `(1,1,1)·(2π/n)`, i.e. `|k|² = 3k²`, so the leading-order
Navier–Stokes decay is `exp(-3 nu k^2 t)`. `2 nu k^2` is the **2-D** TGV rate (`|k|² = 2k²`).

Reproduced independently (`audits/m18155/verify_tgv_reference.py`, monolithic only, no MPI):

| n, steps | rel-L2 vs `exp(-2νk²t)` (delivered) | rel-L2 vs `exp(-3νk²t)` (corrected) | ν_eff fitted under 3k² | ν_eff vs ν=(τ−½)/3 |
|---|---|---|---|---|
| 32, 200 | 34.706 % | **8.713 %** | 0.051326 | +2.65 % |
| 64, 400 | 24.887 % | **17.632 %** | 0.051697 | +3.39 % |

The RMS-decay fit lands within 3.4 % of the imposed viscosity when the exponent uses `3k²` — independent
corroboration of the corrected exponent that does not rely on field shape.

Consequences: (a) the mission's **FAIL conclusion is still correct** — 17.63 % > 15 % even against the right
reference, because `U0·k·t = 1.57` at t=400 makes harmonic content genuinely O(1) — but (b) the stated root
cause is wrong: the dominant, fixable part of the 24.887 % was the factor 2/3 in the exponent, not "the basis
only carries the linear mode"; (c) the report table row "终点衰减比 e^{−2νk²t} = 0.8087" is self-contradictory
— `e^{−2νk²t}(400) = 0.6801`, while 0.8087 is the numeric/analytic amplitude ratio produced by the wrong (too
slow) reference. A mission that had fixed this would have needed a 15 %-gate decision on 17.63 %, and would
still have had to report an honest FAIL.

## 4. Level determination

- **L0** documentation only — exceeded (code + tests + run artifacts).
- **L1** math/unit validation — satisfied: PackInfo set equals OSS `_extend_dir` per direction, pack/unpack is
  a lossless permutation, float64 weights, solenoidal initial state, BGK conservation.

  2-rank gloo slab, 4 arms, `results.json`/`table.csv`), non-placeholder, tests green on re-run.
- **L3** system integration — **denied**: the shipped `multi_gpu.D3Q19GlooTransport.exchange_ghosts` was not
  touched, no product/solver import of `xval_mpi_ghost_fused` exists, so the 3.8× byte cut is not available to
  any user of the library. The headline "移植进 TensorLBM x-slab D3Q19 传输" overstates this: the transplant
  lives in an isolated `xval` package that *replicates* the shipped path for A/B.
- **L4** benchmark validation — **denied**: no `tensor_benchmark_cases` row; the declared physics gate FAILs
  (17.63 % best case, 24.887 % as delivered); the declared 4-config matrix is 1/4 delivered; the delivered
  figure stage does not reproduce (`KeyError 'n64_r4'`).
- **L5** — not applicable.

## 5. Severity-ranked findings

1. **Blocking (for L4) — benchmark case never registered**: 0 rows for the anchor; nothing to adjudicate
   `got` against. Remediation: register the three metrics with tolerances (15 % physics, 0 identity, exact
   byte ratio) and a ref_source.
2. **Blocking (for L3) — no integration**: selective exchange not wired into `D3Q19GlooTransport`; headline
   overstates scope. Remediation: add `selective=`/`persistent=` flags to the shipped class and route a
   solver test through them.
3. **Major — reference formula defect** (`case.py:decay`, `predeclared.json:baseline_control`): `2νk²` for a
   3k² field; inflates the reported error by 7.25 pp and mis-attributes the residual. Remediation: exponent
   3νk² (or a component-wise analytic solution), plus a regression test pinning the fitted ν to ±5 %.
4. **Major — incomplete matrix reported as complete**: 1/4 configs in `results.json`, captions claim 4.
   Remediation: re-run `n64_r4`, `n32_r2`, `n32_r2_f64` (cluster) or restate the captions as 1 config.
5. **Minor — artifacts not reproducible from the delivered driver**: figure stage raises `KeyError` on the
   delivered `results.json`; `serial.series` is empty and `serial.step_ms/mlups` are null, yet 图1 needs it;
   `fig1_tgv_decay.png` is missing while report ④ promises it.
6. **Minor — report figures not embedded**: `figures[]` has only `{name, caption}`, no `png_base64` payload.
7. **Minor — delivery never committed** (`head_commit: null`, all paths `??`); evidence only resolvable after
   this audit transplanted the files.

## 7. Disposition
