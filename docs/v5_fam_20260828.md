## TL;DR

fam 语料的 **aft_sail 族**（`sail_x_mult = 1.3` 常数 × 28 个 LHS Re）正是
v5 通道能吃到、v3/v4 条件化看不见的**第二组 sail 轴向位置对比**——而且
1.3 恰好是 sailx12 标注（0.7/0.85/1.15/1.4）没盖到的值。把它并进 v5
语料（v4 274 + sailx12 + aft 28）：**ext trend ratio 0.531 → 1.067**，
#258 遗留的"幅度欠拍 ~2×"基本收口（每 Re ratio 1.065–1.182，10/10 种子
正号，rho = −1.00），**主语料无代价反而略好**（test-55 0.514% → 0.498%，
mother guard 0.426% → 0.409%，fresh12 0.212% → 0.062%），护栏分布不变
（ok 54 / review 1）。全 112 族行（fam112）**是净亏**：test-55
0.514% → 0.635%，blunt 族 serving MAPE 17.7%——船型族需要广义几何编码
（#241 echo 线），不属本 PR。盲通道控制臂（aft 行进语料、ch9 抹回
1.0）ratio 也有 1.148：**增益的大头来自 28 行作为数据（Re 覆盖/正则），
真标签的价值在于稳定性**（每种子全正、per-Re ratio 收窄、canon
1.149 vs 0.796、fresh12 0.062% vs 0.186%、aft 设计 serving 0.065% vs
0.239%）。

## 3. 归因：通道 × 数据的 2×2（aft28blind 控制）

| | 无 ch9 对比数据 | 有（sailx12 或更多） |
|---|---|---|
| 通道在、数据盲 | loslo（#258）：ratio −0.494（噪声，5 种子符号乱） | **aft28blind**：1.148（aft 行 ch9 抹 1.0） |
| 通道在、数据真 | — | base 0.530（仅 sailx12）→ **aft28 1.067**（+28 行真 ch9） |

读法（诚实结论）：

1. **28 行的边际增益大部分来自"行"而非"标签"**：把 aft 行的 ch9 抹回
   1.0（cd/x/aux 照进）ratio 仍翻倍到 1.148——机制上是 28 条宽 Re 网格
   的 with_sail 母型条件样本（含其真 cd 低 ~0.38% 的整体微调）让
   sailx12 已经注入的轴斜率得以稳定表达。#258 的"缺一不可"针对的是
   12 标注的存在性；本控制补充：**在 12 标注存在的前提下，额外数据的
   通道值并非增益的必要条件**。
2. **但真标签配置在所有稳定性口径上严格更好**：per-member 全正且
   per-Re ratio 收窄（1.065–1.182 vs 1.002–1.638）、canon 1.149 vs
   0.796、fresh12 0.062% vs 0.186%、aft 设计 serving 0.065% vs 0.239%。
   服务部署仍应采用 aft28（真标签）配置。
3. fam112 的亏不是 aft 的错：单看 fresh_fam，aft 0.38% 依然最好；亏在
   **船型族**——blunt（`l_over_d 0.75`）的 v3 geo block
   [0.0118, 0.0024, 0, 1.0024] 与母型 [0.0245, 0.0068, 0, 1.0068] 距离
   很近但 cd 差异大（自身 aproj 归一化吃掉了形状差），v5 的第 9 通道
   不携带船型信息，模型无法自洽 → 17.7% serving MAPE，且 test-55 退化
   0.12pp、一条护栏 ok→reject、低 Re 端趋势近零。船型族要走广义几何
   通道（fam cache 的 `geom` / #241 echo 线）——独立工作，不混入本 PR。

## 4. src 交付（新函数，不改老路径）

`src/tensorlbm/ai/active_learning.py`（+185 行）：

- `FAM_AXIS_VALUES` / `FAM_NAMES`：四族 hull-form 轴的规范值（6=slender
  l_over_d 1.30 / 7=blunt 0.75 / 8=long_nose 1.30 / 9=aft_sail
  sail_x 1.30）。
- `load_fam_fragment(cache_path, meta_path=None, *, fam_labels=(6,7,8,9),
  grid=PRODUCTION_GRID)`：把 fam 族行转成 v4 语料 schema——**fam cache
  无 `geo` 只有广义 `geom`**，本函数用 `hullform_geo_block`（与
  `augment_corpus` 同一 CAD 构造）按各族 config 重算 v3 geo block，并
  附 `sail_x_mult` 列 + `v_sail/v_fin/v_solid/aproj_cad/aproj_bare` 计数
  + 各 hull-form mult 列；meta 与 cache 族行按 Re 钉死对齐、族内 mult
  逐行对拍规范值（漂移即 raise）。
- `append_fam_fragment(index, fragment)`：把片段并入 v4 语料——每族一个
  **全新 dsi**（> 语料 max，`augment_corpus` 同约定）保证
  `split_random` 的基座行成员资格逐位稳定；只填语料已有键（`fam` 等
  片段专键丢弃）；语料无 `sail_x_mult` 列而片段含非 1.0 行时 raise
  （防静默丢轴）。

不动：`condition_v5`/`corpus_cond_v5`/`augment_corpus`/UQ/std/温度全部
原样（aft 行的 cond 由既有 `corpus_cond_v5` 读 `sail_x_mult` 列自动生
成）。战役级回归证明：base 臂在新增代码下**逐位复现** #258 v5e10
（ratio 0.530 vs 0.531、test-55/mother/fresh12/护栏全同，per-member
仅 GPU 非确定性 3 位小数差）。

测试：`tests/test_active_learning.py::TestFamFragment`（+173 行，5 例）：
