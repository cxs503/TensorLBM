## 1. 案例介绍：为什么复核这个模块

`roughness_laws.py` 是粗糙度战役的**裁决基准**，不是可选工具：
`tools/run_roughness_sweep.py` 从它导入 `KAPPA / delta_cf_from_delta_u_plus / ittc57_cf /
ittc78_allowance / literature_band / equivalent_ks_plus`，把实测粗糙函数 `ΔU⁺` 换算成摩擦增量
`ΔCf`，再与 ITTC-78 表面粗糙度补贴比对；`src/tensorlbm/rough_channel3d.py` 用它做对数律拟合
（`fit_log_law`）。因此该模块里任何一个常数转写错误，都会直接污染「冰区刮擦脊 / k 型肋条 / 砂粒」
三类形貌的判据，进而污染阻力预报中的粗糙度补贴项。

复核前的事实状态（`grep -rl roughness_laws tests/ benchmarks/` = 0 命中）：**模块零测试、零基准、
零独立复核**，全部数字来自注释里的文献引用。本单即为该验证欠账的闭合。

## 2. 怎么做的：六个独立锚（不复用模块公式）

判据先于动手：每条公式都从**文献的独立表述**重建参考侧，再与模块输出比对。

| 锚 | 文献独立表述 | 判据 |
|---|---|---|
| A ITTC-57 | `Cf = 0.075/(log10 Re − 2)²` 的**已发表制表值**（4 位有效数字，ITTC 7.5-02-03-01.4） | rel ≤ 1e-3 |
| B Nikuradse | 完全粗糙速度律 `U⁺ = (1/κ)ln(y/ks) + 8.5` 与光滑律 `U⁺ = (1/κ)ln y⁺ + 5.0` 在 `y = ks` 处的**差** | abs ≤ 1e-12 |
| C Cebeci | 转捩闭合 `ΔU⁺ = (1/κ)ln(1 + 0.3ks⁺)` 的渐近截距必须是 `(1/κ)ln 0.3` | abs ≤ 1e-6 |
| D ITTC-78 | 补贴 `ΔCf = [105(ks/L)^{1/3} − 0.64]×10⁻³` 的**闭式零点** `(0.64/105)³` | rel ≤ 1e-6 |
| E 动量口径 | `τ_w = ρu_τ²`、`Cf = τ_w/(½ρU²)` ⇒ `Cf = 2/U⁺²` 的**符号推导** | rel ≤ 1e-15 |
| F 双路线 | `ks/L = ks⁺·U⁺/Re_L`（由 `ks⁺=ks·u_τ/ν`、`u_τ=U/U⁺`、`Re_L=UL/ν` 代数消元） | 报告口径差，不做达标判定 |

三条独立重建的要点：锚 B **不用模块的 `NIKURADSE_C = −3.5`**，而是从两条速度律相减得到
`ΔU⁺ = (1/κ)ln ks⁺ + B_smooth − 8.5`，于是 `−3.5` 变成待验证结论（`B_smooth = 5.0` 与 Nikuradse
截距 `8.5` 之差的恒等式），而不是输入。锚 E 同理：`2/U⁺²` 由 `Cf` 定义与壁面剪应力定义消去
`ρ`、`U` 得到，不引用模块注释。

## 4. 注意点（复核中发现并在本单修复/披露的问题）

**D1（已修，文档性缺陷）ITTC-78 零点数字写错一倍多。**
原注释称「raw polynomial 对 `ks/L < 5.3e-7` 返回负值」。闭式解 `(0.64/105)³ = 2.264498e-7`；
在 `ks/L = 5.3e-7` 处 raw 多项式其实是 **+2.0973e-4（正值）**，该断言被机器证伪。
若照原注释选工况，会误以为该点已被裁剪为 0，实际给出 2.1e-4 的补贴（对应 L = 200 m、ks ≈ 106 µm 的砂粒尺度）。已改为闭式零点，并加测试 `test_ittc78_zero_crossing_is_exact_algebra` 钉住（含对原断言的
反证）。

**D2（已修，文档性缺陷 + 新增导出常量）Nikuradse 裁剪阈值不是 2.25 而是 4.1996。**
原注释称「光滑区位移为 0」，但 `max(·, 0)` 的裁剪点是 `exp(−Cκ) = exp(3.5×0.41) = 4.199645`，
**宽于** `SMOOTH_REGIME_KS_PLUS = 2.25`：转捩带 `2.25 ≤ ks⁺ < 4.1996` 内 `regime()` 已报
"transitional"，函数却恒返回 0。行为**未改**（渐近式在该区间本就无定义，返回 0 是保守选择，
且任何改动都会挪动战役既有判据），只把阈值外置为可测常量 `NIKURADSE_CLIP_KS_PLUS` 并写清文档，
由 `test_nikuradse_clip_threshold_is_exp_of_kappa_times_intercept` 钉住。

**D3（未改，仅披露）`ittc57_cf` 定义域下界形同虚设。**
守卫是 `Re <= 100`，而 `Re` 略大于 100 时分母 `(log10 Re − 2)² → 0`，函数返回天文数字
（ITTC-57 的实际适用域约 `1e5–1e9`）。本单不改行为（可能有调用方依赖当前返回值），建议后续
改为显式警告或收紧下界。

**D4（口径性发现，非实现缺陷）两条 ΔCf 路线不可互换。**
战役同时报告「实测 ΔU⁺ → ΔCf（动量/Hama 口径）」和「ITTC-78 补贴」。把二者用代数映射
`ks/L = ks⁺U⁺/Re_L` 对到同一工况后，差值达 **+210% … −21%**，等价于形貌因子 0.38–1.84。
结论（对下游阻力闭合可直接用）：对固定几何，用 ITTC-78 作判据时必须同时报告 (a) 映射所用
`Re_L`、(b) 隐含 `ks_eff/ks_geom`；「固定几何 vs ITTC-78 误差 ≤3%」这类判据本身不是良定义的。
在 ITTC-78 的标定带 `ks/L ≥ 1e-6` 内，两路线差 ≤ 33.5%，仍远大于 3%。

## 5. 局限

1. **不改求解器**：本单是「规律层」复核，没有跑 LBM。`rough_channel3d` 实测剖面 → `ΔU⁺` 的
   端到端链路（拟合窗、采样窗、`smooth_b` 参考）未在本单验证。
2. **ITTC-57 是模型-实船相关线**（含形状效应），不是纯摩擦线；锚 A 只证明实现常数/指数无转写
   错误，不能证明 ITTC-57 公式本身对，也不能把动量路线与它混用时的不确定性拆干净。
3. **F 锚是一阶映射**：用光滑 `U⁺` 做 `ks⁺ ↔ ks/L` 换算，未做「固定 `Re_L` 下粗糙度改变 `u_τ`」
   的自洽迭代；因此 F 的数字只用于声明口径差的量级，不可当作精确换算。
4. 文献侧常数为手工重打（`KAPPA_LIT = 0.41`、`B_ROUGH_LIT = 8.5`、`CEBECI_A_LIT = 0.3`），若与
   模块共享同一记忆错误，本复核无法发现（这是自证边界，如实披露）。
5. 容量纪律：本机 load15 = 120/128，故本单只做轻量（规律层 + 测试 + 文档），未起 LBM 重算。
