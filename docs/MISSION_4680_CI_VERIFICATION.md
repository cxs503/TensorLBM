## 4. Two gates that were not reproduced, and why (no polishing)

* **mypy core gate.** `src/tensorlbm/solver.py:437: error: Returning Any from function declared to
  return "Tensor" [no-any-return]` in `correct_mass` (`return f * (target_mass / current)`). The file
  is byte-identical to `origin/main` (`git diff origin/main -- src/tensorlbm/solver.py` is empty), and
  the sandbox has `torch 2.7.1`, whose stubs type `Tensor.__rtruediv__` as `Any`; CI installs a fresh
  (newer) torch, which is why commit `bfaf6d06` on main removed a redundant `Tensor` cast here. It is
  a toolchain-drift artefact of the sandbox, **not** something this docs-only PR introduces — and it is
  deliberately *not* "fixed" here, because touching `src/` for a Markdown PR would be unrelated churn.
* **`test (3.11)` / `test (3.12)`.** The full 6794-item fast suite was not run to completion: the host
  is shared with several other missions running `-n 16 … -n 24` pytest workers, and detached runs were
  reaped mid-flight. Also `h5py` (a declared dev extra) is absent in this sandbox, so
  `tests/data/test_solver_export.py` fails at import. Consequence: the test signal for this PR rests on
  (a) it being Markdown-only and (b) the bounded runs in §3.
