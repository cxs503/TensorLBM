## ② 怎么做的（方法/流程/工具链）

**流程**：读 CI workflow → 本地逐 job 复现 → 每类红先考古定根因 → 最小改动 + 原子 commit → 本地把该 job 的每一步按 CI 原命令复跑取证。工具链：ruff 0.15.0 / pytest 9.2.0 / mypy 1.18.2 / git + tools/check_repository_layout.py。

1. **lint（ruff check 95 / ruff format 36 文件）**：先 `ruff check --fix`（**只安全修复**，未用 `--unsafe-fixes`）修掉 67 项（F401/I001）；剩余 25 项手判——E722 的 12 处裸 `except:` 在 SDAA 探针脚本改为 `except Exception:`（不再吞 KeyboardInterrupt/SystemExit），F841 的 13 处未读局部变量按站点逐个判定（删除未读液/气掩码、未用邻域 stack 元组、未用 ghost 平面克隆、未用球心/半径、dam-break 死探针块）；最后 `ruff format` 统一 36 个文件（`ruff format --check` 是同一 job 下一步）。
2. **test(3.11/3.12)（tests/test_bfl_suboff.py）**：根因是 `pytest.approx()` 对嵌套结构抛 `TypeError: does not support nested data structures`、对 0-d tensor 抛 `iteration over a 0-d tensor`。修法**只在断言侧**：新增 `_plain()` 把 torch 值展平为 Python 标量/list 再交给 approx；被判定的量、容差（`abs=1e-14/1e-11`）与产品代码不动，**未删除任何断言**。
3. **platform-test（31 个失败 → 四类根因）**：
   - 考古：`git log --oneline --all -- frontend-vue/dist` **为空**（dist 从未入库，`.gitignore` 里就是 `dist/`）；`app/frontend` 早在 `66efae5e "Remove old native-JS frontend, serve Vue3 dist from backend"` 删除。
   - (a) 产品缺陷 2：`/` 与 SPA 兜底直接 `FileResponse(frontend-vue/dist/index.html)`，缺 dist 抛 `RuntimeError`（HTTP 500）→ 改为显式 404，detail 指名 `npm ci && npm run build`。**没有造假 dist 去骗静态文件检查**。
   - (b) 陈旧测试 26：仍在断言已删除的 `app/frontend/**` → `pytest.mark.skipif(...)` 并在 reason 写明 66efae5e 与 Vue 3 未覆盖；不是 xfail、不删断言。
   - (c) SUBOFF 契约漂移 2：`/api/suboff/solve` 的 `hull_type` 改 `Literal["bare_hull","with_sail","full"]`（非法值 FastAPI 直接 422，而非建 job 后失败）；`boundary_layer_at_station` 的 `y+/u_tau` 只依赖 `tau_w`、`ν`，从早退分支提出（δ 积不出时也须给 y+）。
   - (d) 1 个 `live-metrics` 只在全量顺序下失败：job_manager 是全进程共享线程池，测试手写 1.5 s 轮询等完工，排队稍久就拿到空 diagnostics → 改用 conftest 的 `waiter`（120 s 上限），断言 `len(diagnostics)==3` 不变。
4. **repository-layout**：实测**不是**退出码语义漂移——`tests/test_repository_layout.py`（含 `test_cli_pass_failure_and_policy_error_exit_codes`）本地 12/12 绿；红的是第三步 `python tools/check_repository_layout.py` 退出 1（策略只按精确路径豁免历史文件，main 上仍有 7 个根目录文件）。修法：3 个 mission summary → `docs/mission_summaries/`，3 个诊断脚本 → `tools/`（`bench_sdaa_baseline.py` 的 `src/` 解析改 `parents[1]`），`AGENTS.md` 按 README/CONTRIBUTING 同级登记进 policy 的 `root_files`。**没有给被移动的文件加路径例外**。
5. **mypy core gate（lint job 的下一个阻塞步）**：默认 `--follow-imports=normal` 会把 4 个核心模块 import 进来的整包全报（本机跑到 110 s 已 1524 条仍未结束），与下方 `continue-on-error` 的整包 advisory 完全重复且**永不可能绿**。改为 `--follow-imports=silent`（仍完整检查这 4 个文件并用依赖真实注解），整包信号留在 advisory；这暴露 1 条真错并修掉（`solver.correct_mass` 的 Any 返回 → `cast`）。
6. **回退陷阱（最贵的一课）**：`ruff --fix` 在 `src/tensorlbm/free_surface_lbm.py` 删掉的 `build_i_to_g_ownership_transaction` 是**运行时契约**（mutation-replay 契约测试 monkeypatch 该模块属性），删后 2 个测试 AttributeError；用带说明的 `# noqa: F401` 恢复 re-export 并复测。

## ⑤ 注意点（坑/局限/适用范围）

- **F401 自动修复是危险操作**：会删掉"产品代码不直接用、但运行时被 monkeypatch/反射取用"的名字。本单被 CI 抓到 2 个测试因此 AttributeError。经验：对 `src/` 跑 `ruff --fix` 后必须跑覆盖 monkeypatch 的契约测试。
- **dist 不是"忘了入库"**：`frontend-vue/dist` 被 `.gitignore` 明确忽略，属构建产物；因此 service 端对它缺失必须给可执行 404，而不是 500，也不该由 CI 造空目录绕过。
- **mypy 的 `--follow-imports` 语义**：`strict = true` + 默认 normal 会把被 import 的整包纳入报告范围，"core gate" 名不副实且不可达；`silent` 是"只报给定文件"的正确表达。
- **共享线程池的测试**：任何"固定 sleep 轮询等 job 完成"的断言在 CI 顺序下都不可靠，应使用带超时的终止态等待。
- **局限**：本容器无 Python 3.12（CI 用 3.12）与 h5py，故 3.12 专属差异无法本地验证；全量 `-m "not slow"` 套件在本机 2 核上预计 7 h+ 跑不完，改用"被改文件批跑 + free_surface 子集 + app/tests 全量"等价证据；platform-test 中 26 个测试转 skip，Vue 3 前端 i18n/交互回归目前**无覆盖**（已在文件里注明，属遗留欠账）。
- **本地专属失败**：`tests/data/test_solver_export.py`、`tests/test_ai4s_flagship.py` 共 17 例因本容器缺 h5py 失败，h5py 在 `dev` extra 中，CI 不受影响。
