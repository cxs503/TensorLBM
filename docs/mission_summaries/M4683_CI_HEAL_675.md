## 3. Fixes (4 source files + this note + 1 figure)

1. `src/tensorlbm/solver.py` — `correct_mass`: bind the rescale factor to an
   annotated local (`scale: torch.Tensor = target_mass / current`) instead of
   inlining it. The annotation pins the type for the mypy core gate on *every*
   torch stub version, and it is not a `cast(...)`, so it cannot trip
   `--warn-redundant-casts` (part of `strict`) on hosts where the expression is
   already `Tensor`. Arithmetic is bit-identical.
2. `tests/test_control_volume_force.py` — compare `float(bfl_force[0])`
   instead of the 0-d tensor; the physical assertion (`tight_force[0]` equals
   the BFL impulse to `1e-8`) is unchanged.
3. `tests/test_regress_wall_multi_gpu.py` — both obsolete guards are
   **inverted** (same test IDs, so the historical pointer in
   `docs/reports/REGRESSION_REPORT_wall_multi_gpu.md` stays valid) and now
   assert the fixed contract: `wss_from_fneq_3d` must return a finite
   `(nz, ny, nx)` WSS field with finite values on the wall layer. The docstrings
   record the history so the intent is not lost.

## 5. Limitations / follow-up (honest)

* **The PR cannot be *proven* green from here.** Its checks are cancelled before
  any step runs (§1); greenness needs a re-triggered run once the `ubuntu-latest`
  capacity (or the self-hosted routing) is in place. What is proven here is that
  every gate that *can* be executed locally passes on the fixed head.
* The full fast suite (6802 tests, ~40 min on a hosted runner) was **not**
  completed in this session: the machine runs ~15 concurrent agent campaigns
  (capillary-wave convergence, BEM studies, …), and the run was repeatedly
  killed/or crawled past 8 % in 25 min. The three in-scope reds were instead
  reproduced and re-verified individually with the exact failing node IDs.
* 13 tests under `tests/data/` error locally on `ModuleNotFoundError: No module
  named 'h5py'`. `h5py` is a `dev` extra and the LoongArch pip mirror used on
  this host has **no h5py at all** (`pip install h5py` → `Could not find a
  version that satisfies the requirement h5py (from versions: none)`), while the
  hosted-runner image has it. Hosted logs of run 42008133677 show no
  `tests/data` failures, so this is a host artefact, **not** branch content.
  It is, however, a real risk for the self-hosted pipeline migration: a
  `pip install -e ".[dev]"` on a LoongArch runner would fail on `h5py`/(`triton`).
* `tests/test_multiphase_physical_benchmarks.py::test_spinodal_{2d,3d}_physically_separates`
  remain red on `main` in the nightly/full scope (`assert 1.21822e-05 < 1e-05`,
  `assert 1.0 > 2.0`): physically they check spinodal separation thresholds and
  need an actual numerical decision (tolerance vs. physics), which is out of
  scope for a CI-heal of a cylinder-drag PR. Recorded here so it is not lost.
