## ① 案例介绍（背景与对象）

DFG 基准（Schäfer & Turek 1996, NNFM 48, case **2D-2**，Re=100）：直径 D=0.1 的圆柱置于
2.2×0.41 的槽道内（堵塞比 D/H=0.2439，圆柱中心偏置 (0.2, 0.2)），入口抛物线、出口 p=0、
壁面/柱面半程反弹，力用 Ladd 动量交换。四个可对比量：C_D、**C_L 幅值**、St、Δp。
本格点实现 D2Q9 + MRT，网格档 D=20/28/40 个格子直径（440×82 / 616×115 / 880×164），
u_mean,lb=0.0833，步长按 17 个脱落周期给（14000/20000/27200 步）。

被复核的**声明**：该 case 在验证矩阵里判 **failed**，头条指标为 C_L 幅值误差 **+36.04%**（容差 5%），
即"本求解器在 2D-2 的升力幅值上错 36%"。这个数字同时出现在 `STATUS_MATRIX.md` 与
`artifacts/result.json`（`grids.D28.err_pct_cl_amp`），是外部评审判断"我们的升力算不准"的唯一入口。

## ② 怎么做的（方法/流程/关键设置）

原则：**只复核声明，不重跑物理**（本机 load15≈96，容量纪律要求轻量活；重算另单）。
因此全部结论从**冻结的原始时序** `level_D*_u0833.series.npz`（cd/cl/dp 逐步历史）重算，
不改任何物理设置、不改容差、不改参考带。

1. **重建执行路径**：读 `cylinder_dfg.run_case` 的窗口记账与
   `cl_amp = 0.5*(cl_t.max()-cl_t.min())`。
   冻结工件自证了缺陷：`avg_window_start_step = 1` 而 `seed_steps = 1601/2241/3201`，
   且 `avg_window = n_steps` —— 所谓"5 个周期瞬态 + 12 个周期平均"（`repro.sh` 注释）
   **从未实现**：`n_avg = min(n_steps, avg_periods·T)`，而 `avg_periods=20 > 17`（实际跑 17 周期），
   于是 `window = len(hist)`，窗口吞掉了整个含启动瞬态的记录。
2. **两条正交的估计器缺陷**拆开度量：
   - D1 峰峰值估计器（单点噪声/瞬态可任意抬高结果）；
   - D3 窗口记账（瞬态进入统计）。
3. **新估计器（先定后看，与通过/失败无关）**：
   - 瞬态由配置量 `transient_periods` 显式剔除，**不做数据驱动选窗**；
   - 周期由保留段的 ACF 估（与 St 同一 helper）；
   - 保留段切整数周期，逐周期 `A_j=(max-min)/2`，取中位数 + IQR；
   - **报出值 = 脱落频率上的最小二乘基频幅值** `hypot(a,b)`（对宽带噪声无偏；
     逐周期峰统计被 `max(N)` 系统性抬 ≈3σ，单测已钉住）；
   - 诊断项：中位峰峰相对基频的超出百分比，>10% 打 warning（不静默）。
   `CaseConfig` 新增 `min_steps_required = (transient+avg)·T`，步数不够**直接 ValueError**，
   不允许再"静默把窗口退化成整条记录"。
4. **重判（`run.py --rejudge`）**：从冻结 series 重算 cd/cl_amp/st/dp 四项并写
   `artifacts/rejudge_cl_amp.json`；冻结的 `level_*.json` 与 `result.json` **不覆盖**
   （honest FAIL 不可被覆盖；本单只新增可复核的重判工件）。
5. 另修聚合口径 D5：`aggregate()` 改为**从值与参考带重建 `bench` 块**，不再照抄 level 文件。

**误差归因（可加分解，D28）**：整条记录峰峰 1.3604 → 瞬态后峰峰中位 1.1980（**−11.9%**，纯瞬态污染）

即 **+36% 中有 ~14 个百分点是估计器伪差，真误差为 +17.8%**；D40 档真误差仅 **+2.83%**。

**收敛跨度（修正后，D28→D40）**：cd 3.73%、cl_amp **12.66%**、st 0.79%、dp 3.78% —— 均超
矩阵 3% 跨度判据（cl_amp 尤其悬殊），故**收敛判据未满足**。

## ⑤ 注意点（坑/局限/适用范围）

1. **"测试绿 ≠ 数字对"的第二例**：`repro.sh` 注释写着"5 周期瞬态 + 12 周期平均"，
   代码里从未实现，也没有任何测试断言过窗口位置 —— 于是 +13% 的瞬态污染直接进了头条数字。
   本单把该断言补上（`test_config_window_bookkeeping_excludes_the_transient`、
   `test_config_rejects_run_shorter_than_transient_plus_window`）。
2. **峰统计 vs 基频不是口味问题**：单测显示 σ/amp=3% 的白噪声会让逐周期峰峰偏高 ~6%，
   而基频拟合不动。真记录里两者只差 0.9–2.2%（波形接近正弦），所以本单的真误差不依赖这个选择；
   但若将来记录更噪，报峰峰就会把噪声记成"物理误差"。
3. **未重跑**：本单结论全部建立在已知冻结时序上；未验证"修正后的窗口长度下重跑会给出同一数值"
   （理论上应一致：多出的 12 个周期只是被丢弃的瞬态段）。**未做 D≥56 档**，故"真误差是否收敛"仍悬。
4. **参考带溯源弱**：`REFERENCE.md` 自述 Schäfer–Turek 原文 PDF 离线不可达，C_L 带 0.99–1.01 是从
   `benchmarks/roadmap.md` 的仓内旧记录转抄；且原文 Table 3 的主表量是 C_D/Δp/St/L_w，
   C_L 幅值是否为其表列量**未能核实**。这是 WITHHELD 级证据，非本单可解（无网络）。
   反向证据：修正后 D40 = 1.0283，落在带内（+2.83%），未见"带错"的迹象。
5. **未做的检查**（如实登记为 not_run，不算通过）：求解器重跑、D≥56 收敛档、与独立 CFD/文献逐值对表、
   参考带原文核对。

| # | 严重度 | 发现 | 证据 | 处置 |

| D1 | **blocking（声明失真）** | `cl_amp` 用整条记录峰峰值 → 头条 +36.04%，真值 +17.75%（D28），高估 2.0× | `level_D28.avg_window=20000=n_steps`；`rejudge_cl_amp.json` | 已修：基频估计器 + 保留旧值 `cl_amp_peakpick_legacy` 供对照 |

| D5 | major（工件自相矛盾） | level 工件 `bench.dp` 用 paper 单位带 [2.46,2.50] 去比 (0.5ρU²) 归一值 5.499 → **121.7%**，同文件 `err_pct.dp=10.87%` | `level_D28_u0833.json` | 已修：`aggregate()` 从值与带重建 `bench` |
| F4 | minor（溯源） | C_L 参考带 0.99–1.01 系仓内转抄，原文不可达；C_L 未必是原文表列量 | `REFERENCE.md` §Provenance | 登记为 WITHHELD，需联网/原文核对；本单不动参考带 |
| D6 | advisory | 逐周期峰峰超基频 0.9–2.2%（轻微谐波），已作为诊断项输出 | `rejudge_cl_amp.json` | 仅在 >10% 时 warning |

**独立性声明与局限**：审计者与被告是同一仓库的两份代码，因此新估计器**不 import** `criteria/runner`，
也不复用被测的 `cl_amp` 计算；但两者共享同一冻结时序，**无法排除"时序本身错"**
（例如力核缩放错——不过 cd/st/dp 三项同时落在 <5% 内，力核缩放总体错误的可能性很低）。

**处置（disposition）**：request changes —— 估计器与窗口已修并附 9 条不变量测试；
case 状态**保持 failed**（诚实的未收敛），下一步唯一动作是加 D≥56 一档并重跑（重算，非本单范围）。
