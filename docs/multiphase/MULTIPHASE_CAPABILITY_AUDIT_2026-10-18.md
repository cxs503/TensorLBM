# TensorLBM 多相流能力审计与验证计划

- 审计对象：`cxs503/TensorLBM`，基于 `main` 当前代码与仓库中已有的验证记录
- 审计日期：2026-10-18
- 状态：**静态代码/证据审计；本次没有在远端 GPU/本地环境重新执行全部数值算例**
- 用途：建立后续修复和基准验证的可追踪基线，不是对软件已通过验证的认证

## 1. 执行摘要

TensorLBM 已有多种多相流实现，但当前证据不足以将其描述为通过验证的通用三维多相流求解器。最重要的已知阻塞项不是缺少算例数量，而是缺少一个能够同时保持两相密度差、独立调节黏度比、稳定界面并正确响应浮力的三维求解路径。

仓库现有记录 `benchmarks/pending/hadamard_rybczynski_droplet/NOTES.md`（记录日期 2026-09-29，基线 `e717b464`）给出了 Hadamard–Rybczynski 浮升液滴基准的 FAIL 结论。该结论针对所记录的基线和已探测实现；修复后必须重新运行，不能自动外推为当前 HEAD 的完整测试结果。该记录同时指出 3D SCMC 作用力符号文档与实现行为不一致、Color-Gradient 总密度对比衰减、SC-MCMP 压力压塌/组分反转，以及 Allen–Cahn 液滴溶解等问题。

## 2. 模块清单与成熟度

| 模块 | 当前实现覆盖 | 审计判断 | 主要缺口 |
|---|---|---|---|
| `src/tensorlbm/multiphase.py` | D2Q9；SC 两组分、SC 单组分、Color-Gradient、Free-Energy 相关实现及伪势函数 | 研究原型/需逐模型验证 | 2D 与 3D 不能假设等价；需验证伪势符号、状态方程、独立物性控制和界面基准 |
| `src/tensorlbm/multiphase3d.py` | 文档主路径为 D3Q19 Shan–Chen 两组分；复用若干伪势函数 | 3D 实现存在，但不能据此判定 3D 多相能力完整 | 组分作用力符号、总密度对比稳定性、不同松弛时间偏差、静态液滴/浮升液滴基准 |
| D3Q27 多相族 | 相关实现及边界工具存在于其他模块 | 需要单独审计，不能从 D3Q19 结果推断 | 力项、方向集、bounce-back 方向索引和回归测试必须成套验证 |
| `src/tensorlbm/phasefield/free_energy.py` | 双阱自由能与 `-phi grad(mu)` 类界面力 | 适合进一步研究，但并非已验证的高密度比浮升模型 | 需验证守恒、化学势、表面张力、密度模型及黏度比表达能力 |
| Allen–Cahn 路径 | 存在单独的相场演化实现 | 目前不应作为已验证的液滴/气泡主求解器 | 现有记录报告液滴溶解、相场体积不守恒、迁移率/松弛参数硬编码、表面张力力项缺少曲率依赖等问题 |
| Free-surface / dam-break / water-entry | 有自由液面应用和工程算例入口 | 与通用黏性两相液滴模型区分 | 单流体+自由面标记不能替代两相各自具有黏度与密度的界面求解器 |

## 3. 证据分级

### 已有直接证据

1. 当前 `multiphase.py` 的模块文档列出四类二维模型：SC 两组分、SC 单组分、Color-Gradient 和 Free-Energy。
2. 当前 `multiphase3d.py` 的模块文档将三维主实现定位为 D3Q19 Shan–Chen 两组分，并明确单组分及 Color-Gradient 三维对应路径可后续扩展。这说明不能把 2D 模型清单直接当作 3D 模型清单。
3. `tests/test_multiphase.py` 包含形状、均匀场力、碰撞阶段质量守恒、streaming 后总质量、配置合法性等测试。这些测试有价值，但本身没有验证 Laplace 压差、寄生流幅值、网格收敛、液滴终端速度或长期界面稳定性。
4. `benchmarks/pending/hadamard_rybczynski_droplet/NOTES.md` 对历史基线记录了以下发现：
   - SC-MCMP 三维组分作用力的 G 正负号说明与实际分离/吸引行为不一致；
   - Color-Gradient 路径中密度对比随演化衰减，且其单松弛时间配置将密度比和黏度比耦合；
   - SC-MCMP 浮升液滴探测出现组分反转或混合；
   - Allen–Cahn 探测中的液滴消失，且缺少相场体积守恒机制；
   - 现有三维路径没有在该基准上证明同时具备稳定总密度差和独立黏度比。

### 重要限制

- 历史基准记录不是本次重新执行的日志；不能声称本次已经复现或修复这些缺陷。
- 静态审计不能替代 CUDA/GPU 数值运行、长时间测试、性能测量或独立代码审查。
- 所有“修复完成”都必须以新提交上的回归测试和基准产物为准。

## 4. 优先级缺陷清单

### P0 — 先处理

**MP-001：3D SCMC 作用力符号与文档约定不一致**
- 证据：历史 Hadamard–Rybczynski 验证记录 G1；`multiphase3d.py` 中函数文档将 `G_12 > 0` 描述为排斥/相分离，而历史探测报告相反行为。
- 处理：从离散邻域求和定义出发，推导实际离散力方向；添加两组分界面分离/混合的最小测试；统一 D3Q19、D3Q27、配置验证、注释与示例参数。
- 验收：正负 G 的行为由测试明确锁定；默认配置不得悄然产生混合态并仍报告有效表面张力。

**MP-002：缺少静态液滴物理验收**
- 证据：现有测试主要检查张量形状、均匀场力和质量守恒；历史记录指出部分静态液滴测量发生在混合态，测得的有效表面张力无效。
- 处理：新增可重复的二维圆滴与三维球滴基准，记录内外压差、拟合曲率、最大/均方寄生速度、各组分质量和密度对比。
- 验收：压差对曲率拟合满足预注册误差阈值；多档分辨率呈收敛趋势；无 NaN/Inf；初始混合态或失去界面对比时必须判失败。

**MP-003：三维浮力液滴缺少可用求解路径**
- 证据：历史 Hadamard–Rybczynski 基准报告所有已探测模块均未通过“密度比与黏度比独立、界面长期稳定”的可行性门槛。
- 处理：暂不将任何现有 3D 模型宣称为该类问题的默认求解器；以静态液滴通过为前置，再推进低雷诺数终端速度基准。
- 验收：分别扫描密度比与黏度比，终端速度与解析式/参考结果对比，并提供网格、时间步和误差数据。

### P1 — 基础界面能力稳定后处理

**MP-004：Color-Gradient 的物性独立性与总密度对比**
- 处理：审计碰撞、扰动、重着色步骤及组分松弛时间；分离“保持尖锐界面”与“物性独立控制”两个验收目标。
- 验收：报告各组分质量、总密度对比、界面厚度、黏度比和寄生流随时间变化；不允许仅以张量有限或总质量守恒判通过。

**MP-005：Allen–Cahn 相场演化的守恒与界面力**
- 处理：明确选择守恒型 Cahn–Hilliard 或带体积校正的 Allen–Cahn 方案；暴露迁移率、界面宽度、松弛参数；重新推导表面张力项并加入固体边界处理。
- 验收：无流静态液滴长期体积/相场质量漂移有明确阈值；不同界面宽度与分辨率测试通过；与自由能模型的变量含义和接口不混淆。

**MP-006：D3Q19/D3Q27 边界 API 防错**
- 证据：历史记录指出通用 3D bounce-back 对 19 方向索引硬编码，而 D3Q27 有单独的方向集实现。
- 处理：使边界算子显式绑定离散速度集，或提供严格分开的类型/接口；添加错误方向数的拒绝测试。
- 验收：D3Q19 和 D3Q27 各自通过静止壁面与动量反弹测试；错误方向集不能静默运行。

## 5. 验证矩阵与建议门槛

下表是建议在运行前冻结的初始验收门槛；如果参考论文/解析解或格子参数要求不同，应在基准配置中说明理由后调整，不能在看见结果后临时放宽。

| 阶段 | 基准 | 量化指标 | 初始门槛建议 |
|---|---|---|---|
| V0 | 均匀两组分周期域 | 分组分质量、总质量、有限性 | 无 NaN/Inf；每步质量误差受浮点容差控制 |
| V1 | 静态 2D 圆滴 | Laplace 压差、寄生速度、质量漂移 | 至少 3 个半径；压差-曲率线性拟合 R² ≥ 0.99；相对质量漂移 ≤ 0.1%（运行 10,000 步，需同时注明格点/舍入影响） |
| V2 | 静态 3D 球滴 | Δp–2σ/R、寄生速度、密度对比 | 至少 2 个分辨率；拟合 R² ≥ 0.99；界面和目标密度对比持续存在 |
| V3 | 独立物性扫描 | ρ 比、μ 比、稳定步数 | 至少 3×3 物性组合；实际测得物性与配置值逐一报告 |
| V4 | Hadamard–Rybczynski 浮升滴 | 终端速度、Re、质量和半径 | 只在低 Re 适用条件成立时比较；速度相对误差目标 ≤ 10%，并做网格/时间步敏感性分析 |
| V5 | 液滴剪切变形/碰撞 | 变形率、界面拓扑、组分质量 | 与适用范围内解析理论或可信参考数据对比 |
| V6 | 3D 溃坝/自由液面 | 前沿、液柱高度、质量 | 对照可信实验/公开参考数据；预先定义采样时刻和误差指标 |

备注：R² 和误差门槛是工程验收起点，不代表所有 LBM 参数区间都应自动达到；若不满足，必须给出模型适用性、网格分辨率或参考数据方面的可解释原因。

## 6. 开发顺序与交付物

1. **冻结审计基线**：保留当前失败记录、参数和日志；新增机器可读的基准清单，不覆盖历史证据。
2. **修正符号与离散方向约定**：先解决可通过小测试明确证明的 P0 缺陷。
3. **建立静态液滴验证工具**：统一输出 JSON 指标、CSV 曲线、参数快照、日志与失败原因。
4. **在静态液滴过关后再做浮升滴**：避免在混合态或寄生流主导的状态下测终端速度。
5. **再评估模型选择或重构**：只有在相同基准矩阵下比较 SC、CG、Free-Energy/相场后，才决定哪条路线作为默认三维模型。
6. **加入 CI 分层**：小尺寸/短时物理 smoke test 进常规 CI；较长的 3D/GPU 基准使用手动或定时工作流，并上传原始指标和图像产物。

## 7. 当前结论

- **可以确认**：TensorLBM 有多种二维多相流算法实现及至少一条三维 Shan–Chen 两组分实现路径。
- **不能确认**：项目已具备经过验证的通用三维多相流能力，或能可靠模拟高密度比、独立黏度比的浮升液滴/气泡。
- **首要技术目标**：建立静态液滴热力学验证，再通过独立物性扫描与 Hadamard–Rybczynski 基准。
- **本报告性质**：基于当前源码结构与仓库历史证据的审计计划；不是一次已完成的 GPU 数值回归测试，也不修改求解器物理算法。
