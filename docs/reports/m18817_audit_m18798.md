## ① 案例介绍（物理背景 / 几何 / 参数）

被审对象是 TensorLBM 的 D3Q19 x-slab 分布式 ghost exchange 上一轮（R1，m17995）XVAL 的返修交付：把 lbmpy/waLBerla 的
**选择性（PackInfo）交换**——只打包/发送/解包 `cx=±1` 的 5 个跨越群（D3Q19 每面 5/19）——移植进已发布的
`D3Q19GlooTransport`，并修正 R1 的解析锚缺陷。物理验证算例是 **3D 单模 Taylor–Green 涡**：

```
u =  U0 sin(kx)cos(ky)cos(kz) e^{-3 nu k^2 t},  v = -U0 cos(kx)sin(ky)cos(kz) e^{-3 nu k^2 t},  w = 0,  k = 2 pi/n
```

几何：`2π` 立方周期盒，`(19, nz, ny, nx)`，x 为 slab 轴、y/z 秩内周期；D3Q19 BGK，`dt=dx=1`，`rho0=1+O(U0²)`。

| 参数 | 取值（无量纲） |
|---|---|
| τ / ν | 0.65 / 0.05（敏感性另跑 τ=0.60 → ν=0.0333） |
| n | 16 / 32 / 64 |
| U0（振幅阶梯） | 0.04 / 0.01 / 0.0025 → Re_k=U0/(νk) = 8.1 / 2.0 / 0.51 |
| Ma = U0√3 | 0.069 / 0.017 / 0.004 |
| steps | 200（n=16,32）/ 100（n=64, 产品臂） |
| dtype / ranks | float64；2 ranks（消融）/ 4 ranks（产品路径） |
| 参考锚 | Stokes 3νk²（连续）、6(1−cos k)（格点特征值，与 3k² 差 k²/12 = 0.32%@n32、0.08%@n64） |

## ⑤ 注意点（踩坑 / 局限 / 适用范围）

1. **交付的 repro driver 与报告叙述不一致**：`run_xval.py` 只要含 xval 类配置就 `KeyError: 'kind'`（`run_xval.py:326 → _arm_rows:151`，`campaign.run_config` 返回体无 `kind`），`table.csv`/`gates.json` 从未由它产生——仓库数字出自 `make_artifacts.py`。`REPORT.md §6` 写「same driver executed locally」表述不准。
2. **门槛 fail-open**：单跑 shipped 配置时 `gates.json` 六项全 `pass`，但 `H2.measured=[]`、`H4.ladder_u0_rel_l2=[]`——零测量判通过，只跑子集会产出「空洞全通过」。
3. **校验路径二次交换（既有缺陷，非本 commit 引入）**：`step()→stream()→validate_ghosts(peer=None)` 在选择性模式下再次 `_selective_exchange`（default 模式同样再发全 19 群），故实测 4 次 isend/4 次 irecv；两臂同倍翻，**5/19 比值成立**，但 §3 表的绝对字节是账目口径（真实 2 倍）。
4. **无注册基准**：`tensor_benchmark_cases`/`tensor_xval_cases` 该锚点 0 行，15% 只是 owner 通用带，不能被机器复核。
5. 适用范围：clamp 在线性区（Re_k ≤ 2.1）与 n ≥ 32；n=16 与 U0=0.04 的残差是离散/非线性项，作者已如实标 FAIL，**不是 ghost 通信误差**（该路径 identity 恒为 0）。
