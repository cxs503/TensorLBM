# Mission 368 补报：M4·P2 跨卡域分解框架固化

> **任务编号**: 368 · **仓库**: TensorLBM · **日期**: 2026-10-30  
> **判定**: honest-FAIL（正确性 PASS，性能未达标）

---

## 1. 案例介绍

### 1.1 物理与工程背景

Lattice Boltzmann Method (LBM) 的高分辨率三维模拟（如 SUBOFF 艇体绕流 Re=10⁵+、船尾伴场大涡模拟）需要数十亿格点，单卡显存与算力均不足。跨卡域分解（Domain Decomposition, DD）是将计算域切分到多块加速卡上并行求解的核心基础设施。

### 1.2 任务目标（原单 M4·P2）

| 判据 | 目标值 | 说明 |
|------|--------|------|
| 正确性 | 4 卡 vs 单卡 L2 < 1×10⁻⁶ | 域分解后流场与单卡参考解一致 |
| 加速比 | ≥ 2.8×（4 卡） | 并行效率 ≥ 70% |
| 工件 | `artifacts/m4_dd.json` | 含每卡设备证据 + 计时 |

### 1.3 技术路线

对齐 `docs/triton_distributed_notes.md` 既有经验：
- **NCCL contiguous**：halo buffer 连续内存，零拷贝通信
- **Q padding**：分布函数补齐到 2 的幂次，优化向量化
- **Force all-reduce**：外力项全局归约保证一致性

---

## 2. 方法 / 流程 / 关键设置

### 2.1 实现方案

纯 PyTorch 实现，核心组件：

1. **域分解器** `DomainDecomposition`：沿 z 轴均匀切分，每 rank 持有 `nz_local = nz / n_devices` 层
2. **Halo Exchange**：每步碰撞-Streaming 后执行相邻 rank 间的分布函数交换（2 层 halo，D3Q19 对应 19 个方向）
3. **宏观量归约**：力/阻力等全局观测通过 all-reduce 汇总

### 2.2 测试配置

| 参数 | 值 |
|------|-----|
| 格子类型 | D3Q19 |
| 网格 | 32 × 16 × 16 |
| 总格点数 | 8,192 |
| 松弛时间 τ | 0.6 |
| 步数 | 20 |
| 设备数 | 4（CPU 模拟） |
| 每 rank 子域 | 16 × 16 × 8 |

### 2.3 工具链

- PyTorch 分布式（`torch.distributed`，gloo 后端）
- 计时窗口禁 co-tenancy（`torch.cuda.synchronize` 等价 CPU barrier）
- 位对拍：单卡串行参考 vs 4 卡并行结果逐格比较

## 5. 注意点

### 5.1 性能未达标的根因分析

| 因素 | 影响 | 说明 |
|------|------|------|
| **CPU 模拟** | 主要 | 4 进程在 CPU 上有进程间通信开销，无 GPU 并行加速 |
| **域过小** | 主要 | 8,192 格点，每卡仅 2,048 格点，通信/计算比极高 |
| **步数过少** | 次要 | 20 步不足以摊销初始化开销 |
| **gloo 后端** | 次要 | CPU 分布式后端，非 NCCL 高速互联 |

**关键洞察**：工件 JSON 中已注明 `"note": "CPU simulation - real speedup requires multi-GPU hardware"`。性能判据的测试环境不满足前提条件。

### 5.2 框架本身的正确性

尽管性能未达标，**框架实现的正确性已验证**：
- Halo exchange 逻辑正确（位精确匹配）
- 域切分/聚合无数据丢失
- 宏观量归约一致

### 5.3 适用范围与局限

- **当前验证范围**：D3Q19、均匀切分、周期性边界、CPU
- **未验证**：D3Q27、非均匀切分、壁面边界、多 GPU（CUDA/SDAA）
- **后续工作**：需在 SDAA/GPU 集群上复测，预期可达 ≥2.8× 加速比

### 5.4 踩过的坑

1. **小域通信开销**：8K 格点的 halo exchange 耗时与计算耗时相当，Amdahl 定律限制
2. **CPU 多进程开销**：Python multiprocessing + gloo 的启动/通信开销远大于 GPU NCCL
3. **计时窗口**：需确保 warmup 后计时，避免首次分配内存的干扰
