# SDAA 首个物理验证案例：2D Couette 流解析对照

> **设备证据行**：`torch.sdaa.get_device_name(0)` → **`/dev/tcaicard5`**（SDAA 卡，Torch-SDAA 后端，torch 2.7.1）

## 1. 案例概述

| 项目 | 值 |
|------|-----|
| 案例名 | 2D Couette 流（移动上壁剪切流） |
| 物理问题 | 两平行平板间剪切流：上壁以 U₀ 运动、下壁静止，x 方向周期 |
| 解析解 | u(y) = U₀ · y / H_eff（线性剖面，对任意 Re 精确成立） |
| 格子 | D2Q9 |
| 碰撞 | BGK（τ=0.8, ν=0.1） |
| 边界 | 半程反弹（pre-streaming 变体）+ 移动壁动量注入 |
| 驱动 | 移动壁（上板 u=U₀，x 周期通道） |
| 外推 | 无（extrap: none） |

## 2. 运行配置

| 参数 | 值 |
|------|-----|
| 网格 | 64×62（ny=64, nx=62, H_eff=62 流体行） |
| τ（松弛时间） | 0.8 |
| ν（运动粘度） | 0.1 |
| U₀（上壁速度） | 0.05 |
| Re | 31.0 |
| Ma | 0.087 |
| 主步进步数 | 500 |
| 时间平均步数 | 200 |
| 编译模式 | eager（纯 torch，无 triton，无 torch.compile） |

## 3. 设备证据

运行脚本 `scripts/sdaa_first_case.py` 在 SDAA 设备上执行，输出中包含：

```
torch.sdaa.get_device_name(0) = /dev/tcaicard5
device = sdaa
```

- 所有张量（分布函数 f、壁面掩码、速度场）均创建在 `torch.device("sdaa")` 上。
- 库函数 `tensorlbm.d2q9.equilibrium/macroscopic` 和 `tensorlbm.solver.collide_bgk/stream` 自动通过 `f.device` 将常量（C, W, OPPOSITE）放置到正确设备，无需修改库代码。
- **Triton 绕行**：本案例使用纯 torch eager 模式，不依赖 triton 内核。库的 `compile_route` 模块在 SDAA 上会自动回退到 eager（因 teco_inductor 后端不完整），本脚本直接跳过 compile 路径，从源头避免 triton 依赖。

## 8. 结论

- **SDAA 设备上首次跑通有解析对照的 LBM 物理案例**，设备证据行可溯源至运行输出。
- L2 相对误差 0.018%，远低于 3% 判据，与已验证的 CPU 结果（H=40: 0.0198%, H=80: 0.0146%）量级一致。
- 纯 torch eager 路径，无 triton 依赖，无需绕行开关。
- 总墙钟 3.08 秒，远低于 10 分钟限制。
