# 点对点参考回归门的精度容差策略（round 4）

**锚点**：`XVAL-LBM-POINTWISE-REFERENCE-REGRESSION`（lssfau/lbmpy 的 pointwise-reference-regression 做法）  
**仓库**：TensorLBM  ·  **目录**：`xval/XVAL-LBM-POINTWISE-REFERENCE-REGRESSION/tolerance/`  
**参考束**：`xval/XVAL-LBM-POINTWISE-REFERENCE-REGRESSION/d3q19/refdata/pointwise_d3q19_v1.npz` sha256=`b02d92e007d1e8ae…`（未改动）  
**被测门**：`tests/test_xval_pointwise_d3q19_refdata.py`，阈值 eps_inf ≤ 1e-10

## 1. 案例介绍

round 1–3 已把 D3Q19 整步（`Stream∘Collide`）的点对点参考冻结为 npz 束（逐数组 sha256），
并把仓内 5 条 kernel 臂钉在 `eps_inf ≤ 1e-10`（fp64）上。但两个前提一直是**断言而非测量**：

1. 这个 1e-10 的容差在**降精度执行路径**（fp32 算术 / fp32 内存 / fp16 / bf16）上是否还成立？各精度的噪声地板是多少，因此各精度可用的阈值是多少？
2. 有了这个地板，门**还能看见多大的回归**？若一个门分不清「tau 漂 1%」和舍入噪声，它在那个精度上就不是回归门。

被审计的旧证据：round 1 `summary.json` 的 `fp32_sensitivity[*].eps_scaled_inf_fp32_rounding == 0.0`。
该行把 `fp32(内核_f64)` 与 `fp32(参考_f64)` 相比，而两者在 fp64 上本已吻合到 ~7e-16，
**两次 cast 结果按构造完全相同 → 恒等于 0**。它测的是 cast，不是 fp32 算术。
本轮把降精度放进**时间步内**（每步写回舍入 / 全程 fp32 算术），这才是 LBM 舍入真正累积的地方。

物理设置：三维周期盒 `(6,9,13)`（三轴互不相同，轴向转置无法互相抵消），初始场 = 离散平衡 + 正弦 rho/u 扰动 + 1e-3 非平衡噪声，步数 30，tau ∈ {0.55, 0.7, 1.0}，两个初始场（冻结束 seed0 + round-3 生成器 seed1）。

## 2. 方法

* **参考侧不动**：冻结束（lbmpy 符号碰撞 + numpy 定义式 streaming，fp64）是被比较的固定靶。
  为改 dtype 而重推的 fp64 步先做**控制**：它必须复现冻结束（见 表 1），否则一切降精度结论无意义。
* **两种降精度模型**（模型不同、误差来源不同，必须分开报）：
  * `arithmetic=fp32`：整步所有运算（矩、平衡态、碰撞、streaming）都在 fp32 里做 —— 对应真 fp32 kernel。
  * `storage=fp32|fp16|bf16`：fp64 算术，但每步把分布函数**写回**到低精度（就近舍入再提升）。对应「fp64 算 / 低精度存」的设备，也是真 fp32 路径的保守下限。
* **敏感度**：注入相对松弛时间回归 δτ/τ ∈ {1e-12 … 1e-2}，量 t=30 的 eps_inf，与各精度噪声地板对比得到**可检测下限**。
* **策略化**：`admissible_gate = 100 × 噪声地板`（向上取 1 位有效数字）；另给 10× 余量的并行建议，二者都写进 `tolerance_policy.json`。
* 生产代码路径（torch fp64 的仓内 A1 臂）单独跑写回舍入，确认参考步与生产步的噪声地板同量级。

## 5. 注意点 / 局限

* **1e-10 是 fp64 专属门**。真 fp32 算术地板的 1.571e-06 比它高 4 个数量级：
  把 1e-10 原样用到 fp32 执行路径上是**必然的假报警**，不是回归。这正是本轮要固化的结论（已写成测试断言）。
* fp32 路径的 eps 随步数增长（1.035e-06@30 → 3.056e-06@120），所以地板必须**连同步数一起引用**；只报一个数字会低估长跑的门槛。
* 「fp64 算术 + fp32 存储」的地板几乎不随步数增长（6.000e-08@30 → 6.316e-08@120），说明它由**单步写回**主导，而非累积漂移 —— 两种误差机制不同，不可互相替代。
* `fp64` 行与自身轨迹相比**恒等于 0**（同一段代码），所以 fp64 地板一律取「vs 冻结束」的控制值 7.800e-15；这是本轮刻意避免 round-1 那种同义反复的结构性安排。
* 网格只有 `(6,9,13)`、30 步、两个初始场：**地板是配置相关的**。结论（量级排序、fp64 门有效、fp32 门需另立）稳健；具体阈值数字只在本轮配置族上验证过。
* 仓内 A1 臂（torch fp64）只做了写回舍入，没有 torch fp32 算术那一半 —— torch 版 fp32 算术地板未测，标 **not_run**，不作推断。
* 未涉及：含边界（bounce-back/IBM）与非均匀网格的降精度行为；自由表面/多相；GPU 后端实测。

## 6. 误差判定（是否 <3%？）

| 关键量 | 基准 | 误差 | <3%? |
|---|---|---|---|
| 重推 fp64 参考步 t=30 | 冻结 npz 束（lbmpy 2.0 符号碰撞） | 7.800e-15 | 是 |
| 仓内 A1 臂 fp64 t=30 | 同一冻结束 | 9.958e-16 | 是 |
| 仓内 A1 臂 + fp32 写回 t=30 | 同一冻结束 | 6.000e-08 | 是 |
| 真 fp32 算术 t=30 | 同一冻结束 | 1.035e-06 | 是 |
| 真 fp32 算术 t=120 | 同长度 fp64 参考 | 3.056e-06 | 是 |

**逐项回答「是否 <3%」：全部满足。** 但注意这是「与参考实现的数值一致度」，不是与实验的物理精度；
本轮的物理判定沿用 round 3（剪切波/ABC 衰减 <3% 已通过）。本轮的实质结论不是「误差多大」，
而是「**多大的回归还能被看见**」：fp64 门看得见 δτ/τ ≥ 1e-8，fp32 建议门看得见 ≥ 3e-3（10× 余量），
fp16/bf16 存储下点对点门基本失效（地板 8.5e-4 / 7.6e-3）。
