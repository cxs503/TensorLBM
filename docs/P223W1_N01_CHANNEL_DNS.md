# TensorLBM 湍流通道 DNS 臂验证面：Re_tau=180/395/590 平均剖面+雷诺应力+湍动能谱+壁面律

> 在 TensorLBM 原生通道核上打开 DNS 臂（cs=0），跑 Re_tau=178.12/395/590 三档阶梯，对 MKM-1999 DNS 与 Dean 摩阻律逐项判据化，如实给出各档壁面分辨率与未达 DNS 的原因。

## 1. 案例介绍（物理背景/几何/参数表）

平面槽道湍流是壁湍流模型（RANS/LES 壁面函数、SGS 闭合）验证的黄金标准：流向/展向周期、法向两壁无滑移、恒定体积力驱动，统计一维化后与 Moser–Kim–Mansour (1999) 谱方法 DNS 数据库逐点可比。本节点在 TensorLBM 的原生 OpenMP 通道核（D3Q19、TRT、Guo 力项、半程反弹壁面）上打开 **DNS 臂**（Smagorinsky 系数 `cs=0`，逐位关闭 SGS），跑 Re_tau = 178.12/395/590 三档阶梯，并对平均速度剖面、雷诺应力、湍动能谱、壁面律与摩擦系数逐项判据化。

## 2. 怎么做的（方法/流程/关键设置/工具链）

1. **核与碰撞**：`tensorlbm.turbulence.les_chan`（C/OpenMP，D3Q19，TRT 碰撞，魔法参数 Λ=3/16，Guo 体加速度 a=2u_tau²/H，半程反弹壁面）。DNS 臂要求 `--reg 0`：实测在 `188×122×94`、u_tau=0.0125、Re_tau=180 下，正则化（Hermite 投影）碰撞在 tau0−0.5≈4e-3 时 600 步内 umax 冲到 1e6（发散），而纯 TRT 稳定保持 umax≈0.25、rho_min≈0.999 —— 这是**求解器缺陷**，已在本报告 §5 记录。
2. **统计**：每个采样步按 y 层累加 ⟨u⟩、⟨u_i u_j⟩，4 段批均值给出统计误差；壁面剪切由动量交换诊断独立给出，与体力平衡、粘性底层斜率、对数律三条 u_tau 路线互校。
3. **谱**：新增核选项 `--spec-every/--spec-rows` 把选定 y 行的原始速度平面（float32, plane-major）追加写盘，后处理 `tensorlbm.turbulence.channel_spectra` 做 Parseval 归一化的一维谱（Σ_k E(k)=⟨u'²⟩），拟合带**先验固定**（k∈[4, max(12, 0.25k_max)]），不可能靠挪带子把斜率调到 −5/3。
4. **判据**：`tensorlbm.turbulence.channel_dns` 的 D0–D7 fail-closed 门（缺输入=withheld，永不 pass）；`benchmarks/p223w1_n01_channel_dns/gates.py` 从工件重算全部数字。
5. **算力**：本机 128 核（共享、负载>200）；集群队列当日本波长时间不派发，全部计算在控制面本地以 32 线程/案例并跑完成。

## 5. 注意点（坑/局限/适用范围）

- **求解器缺陷（已定位）**：正则化碰撞路径在 DNS 臂（cs=0、tau0−0.5≈1e-3）慢发散；本节点改用纯 TRT 并把它写进 `LesChannelConfig.regularized` 与用例配置，任何复用 LES 默认配置去做 DNS 的尝试都会失败。
- **算力墙**：dy+=1 的 DNS 网格在 Re_tau=590 需 ~8.1e9 格点（本项目 2πh×2h×πh 箱），是现有两节点 7200 s 作业预算的三个数量级以上。实际跑到的壁面分辨率是 dy+=2.97（Re180）与 dy+=5.94（粗档）；Re395/590 的两个档位（dy+=6.58/9.83）在积分过程中发散、未产出统计量，因此在判据表里以 DIVERGED 记账（见 §3.1 与 artifacts/p223w1_n01_channel_dns/attempts.json），不把壁解析 LES 改名成 DNS。
- **箱尺寸**：Lx/h=3.13、Lz/h=1.57 小于教科书 DNS 箱，截断极大规模运动（VLSM），低阶统计量（平均剖面/摩阻）影响小、高阶/谱的惯性子区被压缩。
- **马赫数**：u_tau=0.0125 时中心线 U≈0.3（Ma≈0.5），LBM 弱可压误差 O(Ma²) 是平均剖面 1% 量级偏差的来源之一。
- **谱斜率**：Re_tau≤590 时惯性子区很窄（≤1 个十倍频程），−5/3 拟合的 r² 与斜率偏差都受此限制，D4 判据的容差（±0.20, r²≥0.85）已按此设定。
- **统计窗口**：每档 4–5 个涡翻转 + 4 段批均值，D6 的 2%/3% 阈值是保守判据。

## 7. 结论与后续（诚实边界）

- 本节点**已交付**：DNS 臂验证面（平面谱 dump + Parseval 一维谱 + D0–D7 fail-closed 判据 + 图 + 22 条 pytest），并把尝试过的 10 个配置全部按同一判据记账（DIVERGED 6 个、判据 FAIL 0 个、PASS 0 个、未湍流化 2 个）。
- 本节点**未达成**：Re_tau=180/395/590 三档 DNS 级统计量对标。原因有二且均已量化：(a) 本核在可用参数区间数值不稳定（u_tau=0.0125 的全部配置、以及 dy+≈6 的多种配置在 1e4–4e4 步内发散）；(b) 稳定下来的配置要么未完成湍流化（u_rms 峰值仅为 DNS 的 21%），要么壁面分辨率不足（dy+≈6，缓冲层误差 ~25%）。
- 算力账：dy+=1 的 DNS 网格在 Re180 需 2.2e8、Re395 需 2.4e9、Re590 需 8.1e9 格点；本节点可用的共享 128 核控制面（负载长期 >200）与当日不可派发的集群队列都远不足以支撑。
- 后续（建议按此顺序）：1) 给核加可选的低耗散稳定化（如 entropic/MRT 或受限 SGS）并在 `--cs 0` 下做收敛性测试；2) 支持从湍流场重启，避免每档都靠 3–6 个涡翻转重新转捩；3) 扩箱到 2πh×2h×πh 并把 dy+ 压到 ≤1.5，需要把算力预算提到 ~1e11 cell-steps/档（集群常态可用为前提）。
