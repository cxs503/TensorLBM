## 2. 方法/流程/关键设置/工具链

### 2.1 质检流程

1. **登录平台**: curl POST /auth/login 获取 JWT token
2. **获取报告**: GET /tensor/reports/{id} 获取 markdown 全文
3. **结构检查**: 逐篇核对五节是否齐备
4. **数字溯源**: 到 `/root/tp-agent/work/m{mission_id}/` 的 docs/*.md 与 artifacts/*.json 中 grep 复核
5. **honest-FAIL 检查**: 对比原单结论与报告结论
6. **图件检查**: 验证场量云图+比较曲线是否齐备
7. **误差判定检查**: 验证是否逐项列出且显式回答
8. **结论检查**: 验证是否超出数据支撑

## 5. 注意点（踩过的坑/局限/适用范围）

### 5.1 踩过的坑

1. **API 调用限制**: 部分 curl 命令因安全策略被拦截，需改用文件重定向方式（先 curl 保存到文件，再 python3 解析）
2. **报告重复**: 659 和 662 实质为同一报告（仅尾部差异），需识别并标注
3. **数据遗漏识别**: 报告中标"-"的数据需到工件中核实是否真的缺失

### 5.2 局限性

1. **数字溯源抽样**: 仅抽查 3 个关键数字，未覆盖报告中所有数字
2. **图件内容验证**: 仅验证 PNG 文件存在，未验证图件内容质量（如坐标轴标签、图例完整性）
3. **原单结论获取**: 未能直接获取原单 mission 的结论，依赖报告中的 self-report

### 5.3 适用范围

- **适用**: TensorPlatform 报告质量复审
- **不适用**: 代码质量审查、算法精度验证
