## 1. Case definition (physics, geometry, parameters)

**Sphere in uniform flow.** A rigid sphere of diameter *D* = 1.0 m is placed in a uniform stream in a cubic far-field box; the drag coefficient is non-dimensionalised with the frontal area *A* = πR² and the dynamic pressure ½ρU², i.e. `Cd = 2F_x/(ρU²πR²)`. Two regimes are computed, Re = 100 (steady axisymmetric wake) and Re = 200 (steady, incipient axisymmetry breaking). The D3Q19 and D3Q27 lattices run the *same* case: identical voxel geometry, identical initial state, identical boundary conditions, identical force estimator (wet-node momentum exchange), identical collision family (MRT auto-selected) and identical domain.

| Sphere diameter *D* | 16 cells |
| Sphere radius *R* | 8.0 cells |
| Domain (box, auto: 3.5·D × 3·D × 3·D) | see per-case `domain_lu` |
| Inlet velocity *U* | 0.0500 |
| Time steps | 2000 |
| Reynolds numbers | Re100, Re200 |
| Lattices | D3Q19, D3Q27 |

Reference values used for the error judgement (all numbers interpolated from the report):

| Re | Schiller–Naumann | Clift–Gauvin | DNS (Johnson & Patel 1999) |
|---|---|---|---|
| Re100 | 1.0917 | 1.1092 | 1.0870 |
| Re200 | 0.8056 | 0.7810 | 0.7720 |

> **Reference-value correction (honest note).** The campaign text quotes `Cd = 0.44` for Re = 100. That value belongs to Re ≈ 1000 (Schiller–Naumann gives 0.44 at Re ≈ 900–1000); at Re = 100 every standard source and the present DNS-anchored references give `Cd ≈ 1.09`. The 0.44 figure is therefore *not* used as a reference anywhere in this report — adopting it would have manufactured a −60 % "error" and would have been a fabricated benchmark.

## 2. What was done (method, route, tool chain)

### 2.1 Code activation (gaps G7/G8)

`GeneralSimEngine` previously dead-ended on `LatticeModel.D3Q27`: the enum existed but `setup()` built a D3Q19 equilibrium, `_get_collide_fn()` returned D3Q19 operators, `run()` streamed with `solver3d.stream3d` (q = 19), the far field BC was `boundaries3d.far_field_bc_3d` (D3Q19) and `_save_snapshot()` used `macroscopic3d`. The activated path:

|---|---|---|
| Equilibrium | `d3q19.equilibrium3d_low_memory` | `d3q27.equilibrium27` |

| Streaming | `solver3d.stream3d` | `d3q27.stream27` |

| Force | `momentum_exchange.momentum_exchange_wet_node` (q = 19) | same function, direction count auto-detected (q = 27) |

The step order of the shared, verified stepper `lbm_step_correct.lbm_step_correct` — collide → NoDynamics → half-way bounce-back → stream → far-field BC — is **unchanged**: the lattice is injected through a new `stream_fn` argument plus the existing `bounce_back_fn` hook, and a unit test asserts bit-exact equality with the manual kernel sequence. Combinations without a D3Q27 kernel (wall-function wall treatment, Smagorinsky collisions) raise `NotImplementedError` instead of silently degrading to a D3Q19 kernel.

### 2.2 Three-layer validation ladder

1. **Lattice algebra** (`isotropy_moment_deviation`, exact, 1e-16): the moment tensors Σ w c⊗…⊗c of ranks 2/4/6 against the isotropic tensors built from c_s² = 1/3.

## 3. Results

### 3.1 Lattice isotropy moments (exact algebra)

| Lattice | rank-2 residual | rank-4 residual | rank-6 residual | rank-4 isotropic |
|---|---|---|---|---|
| D3Q19 | 1.11e-16 | 1.11e-16 | 2.22e-01 | yes |
| D3Q27 | 1.67e-16 | 1.67e-16 | 2.22e-01 | yes |

**Finding (falsifies a common shorthand):** D3Q19 is *not* missing 4th-order isotropy — its rank-2 and rank-4 moments are identical to D3Q27's to round-off (residual ~1e-16 with exact rational weights). Both lattices fail isotropy at rank 6 (residual = 2/9 = 0.2222 for each). The two velocity sets differ at rank 6 only through the 8 corner directions (max component difference = 1/27 = 0.037037). Consequently the D3Q19→D3Q27 accuracy gain is **not** implied by an isotropy theorem and must be measured — which is what the rest of this report does.

**Reading:** the axis-aligned wave is bit-identical on both lattices (the axis directions are shared), and so is the pure-edge orientation. The mixed orientations are where the corner directions act. The residual ν error level (~5 %) is the O(k²) lattice truncation common to both lattices, not anisotropy; the *difference between lattices* at fixed |k| is the anisotropy signal, and it is a few tenths of a percent to ~0.6 % of ν — small, and it does **not** favour D3Q27 uniformly (see the orientation spread in the table). This is reported as measured, not as the folklore predicts.

## 4. Notes, traps and limits

1. **Reference value.** `Cd = 0.44` at Re = 100 in the task text is wrong by ~2.5×; the correct anchor is `Cd ≈ 1.09` (S-N 1.0909, DNS 1.087). Documented above; no result is tuned to the erroneous value.
2. **Staircase geometry dominates the absolute error at small *D*.** The voxelised sphere under-resolves the surface (obstacle-cell count is in §3.6); the absolute Cd error is therefore resolution-limited, while the *lattice comparison* is exact (identical geometry).
3. **Force estimator.** Only the wet-node momentum exchange (`mem_variant='wet_node'`, the G12 fix) and the legacy pressure+friction control surface are reported, both without pressure extrapolation (`pressure_extrap='none'`, as the benchmark rules require). The historical standard/pair Ladd sums are *not* used: they carry a spurious +43 Cd free-stream background on staircase spheres (G12).
4. **Separation angle** is a first-order geometric estimate from one-cell azimuth bins on a staircase surface (1° bin). At D = 16 it is **not** a literature value: the measured 128°–141° is far aft of the reference ≈ 84° (Re = 100) / ≈ 90°–93° (Re = 200) because a 16-cell sphere has an over-thick numerical boundary layer that delays separation. Only the *lattice difference* (Δ = Re100 -5.9°, Re200 -6.0°) is used as a signal, and even that inherits the azimuthal discretisation; fine-grid separation angles are out of reach at this node.
5. **Pressure-field L2 difference** `‖p₁₉−p₂₇‖/‖p₂₇‖` is a cross-lattice difference, not an error: there is no analytic pressure field for a sphere at Re = 100/200. It bounds how much the lattice choice can move the field at fixed resolution.
6. **Taylor–Green honesty.** The exact solution used is the z-uniform (extruded 2-D) mode; the genuine 3-D TGV has no closed form, so an exact L2 reference cannot be constructed for it.
7. **Bug found and fixed during this mission (kept in the record).** The first suite execution pinned `physics.viscosity` to the Re = 100 value, so the "Re = 200" group silently re-ran Re = 100 (two identical Cd groups in the JSON). It was caught by comparing the two Re groups before writing any conclusion, fixed by deriving ν = uL/Re from the requested Re, and a regression test (`test_sphere_case_config_applies_reynolds_number`) now asserts Re reaches the engine (`info['Re'] == re` and `tau = 0.5 + 3 nu_lb`). The numbers in this document are from the re-run.
8. **Absolute accuracy is resolution-limited, not lattice-limited.** At D = 16 cells the voxelised sphere gives a Cd error of order 20-30 % on *both* lattices (identical geometry), far above the 3 % / 15 % bands; the D3Q19 acceptance benchmark reaches 3.4 % only at D = 40. Delivering a <3 % sphere Cd therefore requires D ≳ 32 and is out of scope for this node — stated as an honest FAIL, not hidden.
9. **Performance trap (reproducibility note).** `torch.set_num_threads` above ~16 *slows down* these grids (measured 60 ms/step at 8 threads vs 150 ms/step at 24 threads on the same 54 k-cell case) — the sphere matrix is therefore run as 4 processes × 8 threads, and the per-step `torch.isfinite` divergence guard is throttled via `TL_ISFINITE_INTERVAL`.
11. **Low-τ stability of the D3Q27 path (finding).** At Re = 200 / D = 16 the engine's AUTO collision (MRT) runs at τ = 0.512; the D3Q19 kernel stays healthy while `collide_mrt27` loses stability late in the run (max|u|/U jumps from ≈ 1.3 to 6.9, Cd window collapses). The ladder therefore reports that case as an honest FAIL with its stability flag. A separate probe (`benchmarks/d3q27_re200_stability_probe.py`, output `stability_re200_{mrt,trt}.json`) reruns the same case with the TRT kernel on both lattices to separate "D3Q27 is unstable" from "MRT at τ≈0.51 is unstable".
12. **Latent defect fixed in passing.** `CollisionModel.TRT` for D3Q19 used to fall through to the MRT kernel silently (no TRT routing existed in `_get_collide_fn`); both lattices now route the real TRT kernels, so the MRT-vs-TRT comparison above is meaningful.
13. **Not implemented (loudly).** D3Q27 wall-function treatment, D3Q27 Smagorinsky collisions and the 2-D-extruded (periodic lateral) D3Q27 far-field layout raise `NotImplementedError`; no silent fallback exists.

## 5b. Re = 200 stability probe: MRT vs TRT

`benchmarks/d3q27_re200_stability_probe.py` reruns the Re = 200 case with both lattices under the MRT (engine AUTO) and TRT kernels — same grid, same τ — to separate "the D3Q27 lattice is unstable" from "MRT at τ ≈ 0.51 is unstable".

| Collision | Lattice | τ | Cd | err vs S-N | max&#124;u&#124;/U | stable |
|---|---|---|---|---|---|---|
| MRT | D3Q19 | 0.5120 | 0.9750 | +21.03 % | 1.28 | yes |
| MRT | D3Q27 | 0.5120 | 0.5053 | -37.28 % | 6.87 | no |
| TRT | D3Q19 | 0.5120 | nan | +nan % | nan | no |
| TRT | D3Q27 | 0.5120 | nan | +nan % | nan | no |

Reading: the probe is diagnostic, not an accuracy claim. MRT at τ = 0.512 reproduces the accuracy run *bit-for-bit* (deterministic code), D3Q19 healthy / D3Q27 unstable. TRT — which the engine now really routes for both lattices — is *worse* here: with the default magic parameter Λ = 3/16 the anti-symmetric relaxation time becomes τ⁻ = 0.5 + Λ/(τ⁺ − 0.5) ≈ 16 at τ⁺ = 0.512, i.e. far outside the usual Λ ∈ [1/8, 1/4] window, and both lattices return NaN. Conclusion: at this τ the failure is a *collision-operator stability limit at τ → 1/2*, not a property of the 27-velocity set alone; a follow-up node should lower Ma (raise τ), enlarge D, or use the cumulant collision (`collide_cumulant_d3q27`, not yet routed in the engine) before claiming any Re = 200 D3Q27 drag number.
